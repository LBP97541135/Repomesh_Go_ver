## 调用链与声明

[b04.go.txt](b04.go.txt) 为 Go 声明，[frontend.ts.txt](frontend.ts.txt) 的 B04 部分为 TS 映射，均只存附件。当前 Web 使用 `registerProjects` 注册模式，新增 models 注册沿同一方式。入口注入 pool、access、secrets 和 projects.CatalogWriter；models→projects/access/secrets，sources→projects；projects 不反向依赖 models/sources，内部包不依赖 cmd。

| 调用者 | 入口和责任 | 成功／失败后的持有者 |
| --- | --- | --- |
| 模型设置页 | Save(principal, command)，严格信封与完整模型输入；唯一用例持事务 | 确认提交后回原结果；不确定由原 saveId 继续查询／close，不能换键 |
| 恢复页 | GetSave / CloseSave，当前身份与目标 owner，每次重新核验 | close 与 save 同 account/槽位；已提交不撤销；无槽持久终结后阻止迟到保存 |
| models 私有写路径 | prepareSave 在锁外；commitSave 在 tx 内；replaySave 先墓碑／closed 再旧比较器 | prepared 临时材料由本请求清理，独立预扣不退款；已提交 vault 由模型维护负责 |
| projects 目录写口 | 在已持 catalog 写锁的 caller tx 中登记模型或执行版本及默认 | 不独立提交、不更新既有项目；目录映射与业务来源原子一致 |
| 部署 CLI | Import / Get，deployment 身份不来自 JSON | 原 importId 稳定回执；同键同输入优先当前 head/owner 重校验 |
| 受控维护 | RemoveSaveResult，目的隔离的 DestroyInTx | 操作墓碑和权限归属永久防旧键复活，业务秘密不随操作清理销毁 |

内部 Prepare/InsertPrepared 的分离是密码学预扣的需要，不向浏览器暴露分步保存。已在权威记录中绑定的 owner/purpose 是输入解密依据，不能接受浏览器自报秘密引用。

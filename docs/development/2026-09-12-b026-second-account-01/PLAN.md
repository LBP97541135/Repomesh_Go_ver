# 第二账号真实验收计划

本计划只覆盖 LIVE-05 与 LIVE-08 尚缺的第二账号场景。它不重跑已经通过的取消、同账号重连、安装权限负例或分页场景，也不改变自然刷新证据。

## 1. 刷新后只读接管

先核对刷新观察 02 的确认文件、浏览器结果、观察器退出状态和注销后的 session 401。保存本轮 `preflight.json`，只记录文件哈希、通过标志、进程状态与非秘密时间。若刷新失败，保留失败并停止本轮；不得重新登录后把新 epoch 当作自然刷新。

## 2. 建立第二账号最小权限样本

1. 记录专用 App 当前可见性、安装 ID、selected-repositories 范围和三项权限，不记录任何秘密。
2. 将专用 App 临时设为 public，使非 App 所有者账号 B 能完成真实用户授权。不得扩大账号 A 的现有安装仓库范围。
3. 由账号 B 建立一个仅 B 可见的专用私仓，并将该 App 以 selected-repositories 方式安装到 B 的账号且只选择这个仓库。保存稳定仓库 ID，私仓名称只留在受限浏览器现场。账号 A 不得成为该仓库协作者。这个样本只用于证明 LIVE-05 后账号 A 的结果不包含仅 B 可见的仓库。
4. 由账号 A 向账号 B 发出 A 持有的专用私仓协作者邀请；由账号 B 的持有人登录 GitHub 并实际接受邀请。该样本用于 LIVE-08 用户读权撤回。
5. 使用账号 B 完成 RepoMesh 正常登录和必要的 App 授权同意。账号选择、密码、二次验证、授权同意、App 安装和邀请接受均由账号持有人完成。
6. 查询两个专用私仓，保存 B 持有私仓的稳定 ID，以及 A 持有私仓在账号 B 下初始 `userParticipation.status=allowed`、`appCapability.status=allowed` 和观察时间。若 GitHub 组织或账号策略要求额外批准，记录实际阻塞，不绕过审批。

App 可见性与协作者权限是本轮唯一允许的 GitHub 配置变化。每一步先保存前态，再做单一变化，再保存后态。

## 3. LIVE-05 错误账号重连

1. 让账号 A 建立一个新的有效 RepoMesh 会话，保存 actor、连接 revision、epoch、有效 session generation 和仓库结果摘要。
2. 从账号 A 的工作区发起真实“重新连接 GitHub”。在 GitHub 账号选择器中由账号持有人选择账号 B，并完成实际返回。
3. 要求 attempt 终态为 `rejected/ACCOUNT_MISMATCH`；账号 A 的 actor、连接 revision、epoch 和有效 session 不被替换。
4. 要求结果页不显示账号 B 的身份或仓库数据；随后账号 A 的完整分页仓库查询不得包含 B 持有且 A 不可见的专用私仓稳定 ID，也不得披露其名称。
5. 保存 callback 与页面事件时只记录状态码、固定路径、attempt ID、错误码、账号稳定 ID 和 Cookie 是否出现等布尔字段。

任何成功重连、账号 A 连接被覆盖、原会话被错误撤销或跨账号仓库披露都记为 FAIL，并停止后续验收操作，转入第 5 节的必做恢复。

## 4. LIVE-08 用户读权撤回

1. 退出账号 A 的 RepoMesh 会话，再由账号 B 正常登录；确认本轮使用的是账号 B actor，而不是错误账号重连留下的结果页。
2. 重新查询 A 持有的专用私仓并保存读权 allowed 的实际观察时间。该前态必须晚于邀请接受，且由当前 API 往返产生。
3. 由账号 A 移除账号 B 对该专用私仓的协作者权限。保存 GitHub 页面已完成移除的非秘密时间与仓库稳定 ID。
4. 从原 allowed 观察时间起等待超过 60 秒，再用账号 B 的同一 RepoMesh 会话发起新的发现查询。不得修改缓存时间、数据库观察时间或本机时钟。证据必须分别保存 allowed 观察时间、移除完成时间和重查时间，并给出重查时间减 allowed 观察时间的实际秒数。
5. 要求响应不再披露该私仓的名称；记录稳定 ID 是否缺席、coverage、分页游标与请求时间。私仓完全缺席是该场景的正确结果，不能把它混同为 App denied 样本。
6. 再次查询一次，确认旧名称没有因分页或缓存竞态重新出现，然后正常注销账号 B。

## 5. 恢复与结论

本节是成功、失败或中途阻塞后的必做收尾，不得因前一场景失败而跳过。将专用 App 恢复为 private，确认账号 A 的安装仍只覆盖原 selected repository，三项权限保持 metadata read、contents write、pull requests write。移除账号 B 的临时 App 安装；账号 B 对 A 私仓的协作者权限保持已移除。若 B 的用户授权仍列在 GitHub Applications 中，由账号持有人撤销专用测试 App 授权，并记录完成状态。B 持有的专用私仓是否保留由账号持有人决定，但无论是否保留都不得继续安装该 App 或授予账号 A 访问。

需要继续 B03 时，再由账号 A 正常登录 RepoMesh，作为新的后续工作会话；该登录不能反写为 LIVE-09 自然刷新证据。

本轮完成后由未执行主要操作的复核者检查：门槛、账号身份、每次状态转换、60 秒缓存条件、无名称披露、恢复状态和秘密裁剪。只有刷新观察、LIVE-10、本轮 LIVE-05/LIVE-08 及整批复核全部通过，才把 B02.6 和 B02 标为 VERIFIED。

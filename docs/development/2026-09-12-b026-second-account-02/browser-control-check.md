# Browser control helper check

- Scope: most commands only open fixed read-only destinations or inspect allowlisted pages. The guarded `make-app-public` and `make-app-private` commands are the only mutation paths. They require the exact Advanced page, account A, and an unambiguous initial control; they click no transfer/delete controls and never fill or read an input.
- CLI: `node browser-control.mjs <cdp-port> <command>`; open commands also include `open-a-installation`. `inspect-app-advanced` requires the exact Advanced page and account A, then returns only fixed control booleans and bounded counts. `inspect-a-installation` requires account A's exact installation page and returns only `ALL`/`SELECTED`/`UNKNOWN` plus fixed permission-level enums.
- Account B install entry: `open-b-app-install` is accepted only with CDP port 9230 and navigates to the fixed App installation start URL. It requires meta login `bohanxu111` and reports only `B_APP_INSTALL_START`; query strings and fragments are neither returned nor persisted.
- Account B install completion: `inspect-b-install-completion` performs no navigation and requires port 9230 plus meta login B. It recognizes only a fixed settings installation path, its subpaths, or the fixed App installation callback carrying one positive numeric `installation_id`. All candidates must resolve to one ID and one path-class enum; output never includes the path, query, fragment, title, or repository data.
- Visibility mutation: confirmation handling is limited to a visible dialog or open `details` element and one distinct, enabled button whose accessible name exactly matches `Make public` or `Make private`. Typed confirmation, password/2FA, ambiguous controls, or an unmet postcondition returns `NEEDS_HUMAN_CONFIRMATION` with fixed safe fields.
- Static validation: `node --check docs/development/2026-09-12-b026-second-account-02/browser-control.mjs` passed on 2026-09-12.
- Runtime validation: not run; no CDP connection or browser navigation occurred while preparing this helper.

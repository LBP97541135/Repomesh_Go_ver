# 当前账号自然刷新观察

第二账号缺失只阻止错误账号重连和用户读权撤回，不替代或豁免这两项。当前账号的自然刷新及其后的浏览器验证继续独立执行，B02 整体不会因此标为 VERIFIED。

## 执行单元

1. 权限恢复实际 allowed 后，从真实页面执行一次同账号重连，形成可追溯的新基线。只读保存 actor、连接版本、epoch、期限、会话及尝试元数据。
2. Astra 声明观察器与浏览器验收脚本的接口，Sol 实现，非实现者独立复核后启动。观察器只使用专用 PostgreSQL 的只读事务，不读取、解密或重放 token，不修改任何期限，不设置虚拟时钟。
3. 后台观察真实 access_expires_at 前 30 秒的窗口。任何新登录或重连尝试、账号变化、提前或异常版本变化、未知状态都阻止成功判定。短暂 claimed 状态仅在真实窗口内等待，不重置责任位。
4. 只有完整刷新不变量满足，才在同一有效浏览器会话中执行新私仓查询、移动视口检查、实际注销及历史往返，记录实际响应和页面状态。失败停止，不能强行写成通过。
5. 保存实际运行结果并独立复核。缺少第二账号的场景继续 BLOCKED，B03 继续 TODO。

## 编排检查点

主代理准备实际基线与权限恢复证据；两个 Sol 子任务分别负责只读观察器、刷新后的浏览器驱动，文件互不覆盖。代码与基线必须在实际刷新窗口前准备并复核完毕。预计首次自然等待约 8 小时，以真实数据库期限为准。

工具本身的语法与安全检查不计为真实验收。真正通过只能来自新的数据库前后快照和实际浏览器结果。所有运行文件使用独占创建，不覆盖任何旧失败或 r1 发布证据。

# 设计审查后的修订与开工条件

本轮接续[多 agent 审查](../reviews/2026-09-12-design-readiness/README.md)，修正已证实的不一致，并补充可审阅的候选协议。审查报告保留当时的源文件基线和结论；修订后的状态以本文及各唯一专题为准。本文的 R01—R05 是审查编号，不是首批总包中同名的页面恢复决定编号。

本轮不更改历史用户采用记录，不把此前整篇 `proposed` 转为 `accepted`，也不启动产品业务实现。原型一致性修复和 Skill 适用说明沿用既有语义；新终结接口、导航类型扩展、Issue 配置绑定时点仍是具体候选修订。

## 修订归属

| 审查项 | 本轮修订 | 唯一规则与适用范围 | 完成的含义 |
| --- | --- | --- | --- |
| R01：Key 保存永久未知 | 原操作查询保留；增加与保存争用同一唯一槽位的安全终结方案。原操作已提交则返回原结果；终结记录阻止迟到请求保存。 | [保存终结协议](model-settings-browser-api-draft.md#31-r01终结原保存解除未提交操作的未知状态)、[模型浏览器契约](model-settings-browser-api-draft.md)、[内部模型操作](backend-model-operations-draft.md)。 | 候选协议补齐失败恢复分支；需要采用并完成数据库并发验证，才可称真实恢复可用。 |
| R02：测试观察不一致 | 模型列表和应用预览按同一固定快照读取测试观察。 | [模型应用专题](model-project-apply-design.md)及原型源片段。 | 修复内存原型；不改变配置快照，也不把测试通过增加为应用门槛。 |
| R03：重登返回不完整 | 白名单目标覆盖已有会话；消息提交恢复目标标明后续发送批次。 | [认证 Destination](authentication-browser-api-draft.md)、[页面恢复](first-batch-recovery-design.md)。 | 候选契约补齐；浏览器目标解析不授予资源读权。 |
| R04：Issue 配置归属缺失 | 推荐在 Issue 创建事务中绑定可解析的不可变 ProjectConfigRevision；重放、并发应用、秘密失效不改原绑定。 | [Issue 配置绑定](issue-configuration-binding-design.md)、[首批持久化](backend-first-batch-persistence.md)。 | 存储设计形成候选补充；运行消费仍未接入。接收未来要继续执行的真实 Issue／待办前必须落实关联记录。 |
| R05：Skill 暂缓与验证证据 | 就地说明未使用 Skill 时记录实际工作说明、脚本与来源版本。 | [验证节点](verification-node-design.md)、[ADR-0009](../adr/0009-skill-engineering-deferred.md)。 | 澄清首期适用范围；不引入 Skill 模块或伪造版本。 |

首批总包的 D06、P4、P7、认证 A2 和恢复 R06 随上述候选修订同步；旧 CP16 的技术互核记录保留其当时含义，不再用“无剩余文档分歧”证明修订后全系统已经就绪。原采用的 F01—F04 具体 UI 及创建契约中不受影响的条款保留。

## 分阶段开工条件

| 开发范围 | 当前可做 | 接收真实业务／启用副作用前必须满足 |
| --- | --- | --- |
| 基础工程、已采用页面结构、项目／Issue 查询与持久化代码 | 可按既有契约开发；本次没有实施这些代码。 | 当前权限、事务、操作去重及恢复按对应契约验收；接收供以后执行的真实 Issue／待办还须满足下一行 R04 的绑定要求。 |
| 首批真实管理闭环 | 可并行实现已确定部分。 | 采用并落实 Key 终结、认证返回及必要配置来源；在接收供后续执行的真实 Issue／待办前确定 R04 的绑定语义与存储，不能等消费者上线后猜历史配置。 |
| 真实会话和 Manager 接手 | 可编写受控适配的契约和验证夹具。 | 完成运行配置消费、首条消息、可信输入输出关联及工具授权，见下述 G1—G2。 |
| Worker、跨仓执行及 Loop | 可继续收口协议和验证原生适配能力。 | 完成 G3—G5 的写入责任、实际执行生命周期和换图恢复；不得把数据库状态或模型文字当作外部停止证据。 |

运行缺口统一列在[执行接入门槛](execution-integration-gates.md)。该表把已有待定事项变成具体交付要求，没有代选所有上游补丁或冒称系统问题已全部修复。无需重写 Go DAG 引擎，也无需恢复 Skill 工程。

## 修订检查

本轮检查与原型复现记录存于[修订验证记录](../reviews/2026-09-12-design-fixes/README.md)。文档链接和 JSON 可解析只证明结构正确；原型事件验证只证明模拟交互一致。OAuth、秘密存储、PostgreSQL 并发、真实模型调用和 AgentTeams 全链路仍需实施后验收。

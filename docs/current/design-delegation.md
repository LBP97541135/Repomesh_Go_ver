# 后续设计按建议推进

> **2026-09-11流程已替代：** 用户现要求“之后你们的每一个决策设计需要我同意”。本文以下持续授权及“直接推进、不逐项询问”仅记录历史，不能用于新增或变更设计的自动采用。既有采用清单和准确范围保留；新决策须经用户逐项明确同意，双方讨论最多三轮。当前规则、身份及压缩恢复见[通信约定](../archive/2026-09-12-development-preparation/docs/current/design-communication.md)。

用户最新原话：**之后的待决定都批准，按照建议来。**

这是持续的设计决策授权，替代此前每项设计必须等待用户单独确认的流程。页面与后端对齐后，选择并记录推荐方案、理由及代价，直接推进并向用户报告结果，不再逐项询问。已有明确否决、暂缓范围与业务约束继续有效。尚缺证据的运行能力仍需验证，不把授权写成验证通过。

双方每次设计对齐、同一主题最多三轮、完整通信即时保存及自动压缩恢复规则保持。DESIGN-004 历史仍为 3／3；本次落实新授权，不重开第四轮。当前工作范围仍为设计文档与已授权本地原型。

## 当前创建方案的采用清单

旧项目调查后的用户明确补充：“可以先把仓库关联分析做成在建立issue的时候加一个仓库分析按钮，做成python写的插件”。已采用[建项前仓库分析](issue-creation-repository-analysis.md)及 [ADR-0020](../adr/0020-python-repository-analysis-plugin.md)：可选按钮、Python 分析包、Go 作业与来源管理；结果由用户应用后形成最终选择。历史决策分析和向量数据库未因此一并采用。此为后续选择，不改写下表 P1—P4 原确认来源。

以下选择依本次持续授权采用，不倒填为此前“默认新建会话”或“确定”曾单独批准。

| 范围 | 采用方案 | 理由与代价 |
| --- | --- | --- |
| P1 原子范围补齐 | 新建时的业务会话、Issue、主 ChangeSet、来源关联、真实创建记录、确切输入快照、幂等结果和对应持久待办同一本地短事务；已有会话只增加关联及记录。 | 成功回执完整，接受本地关联与事务维护成本；外部调用在事务后。 |
| P2 运行准备 | 首次保存会话及首条消息后，或页面 Issue 创建提交后，异步准备／恢复项目实例及对应主房间，再由 Manager 接手；已有实例和房间复用。 | 明确提交后自动接续，接受必要运行消耗；项目创建、空会话和只读访问本身不启动。 |
| P3 实时更新 | Issue 详情采用独立 SSE 失效通知，REST 快照为准；持久事件、重连游标及失效后补查。 | 状态及时更新，承担事件与权限恢复维护成本。 |
| P4 来源和命名 | 保存允许字段的确切提交、规范化摘要及版本、可信操作者和来源；Manager 来源引用真实消息。新会话初始标题取 Issue 标题，此后独立改名。 | 可追溯、不伪造聊天，接受必要存储成本；不收集密钥或隐藏推理。 |
| P4 操作保留 | 操作身份在项目保留期内不复用；业务内容删除后仍保留不含正文的最小幂等占位，已物理删除项目的旧身份不可复活。 | 旧请求不因短缓存过期重复建项，接受占位与清理维护。 |
| 两个创建入口 | Manager 受控 MCP 与 Issue 栏表单使用同一业务创建命令及结果查询；Agent 创建能力首期仅向项目 Manager 开放。 | 自然语言与页面结果一致，维护两种可信入口，不重复建项。 |
| 会话关联 | 页面默认新建会话，也可明确选择当前项目有权的已有会话；选择失效时报错，不静默替换。 | 保持默认简单，同时允许承接现有讨论；本次只关联一个来源会话。 |
| REST 基线 | 采用创建条件、POST 创建、原操作查询、详情及房间查询的具体契约；201 首次、200 重放，未知查原键。 | 可据此继续接口设计，承担幂等、权限和并发维护。 |

具体约束见[创建接口契约](issue-page-create-api-contract.md)和[双入口机制](manager-create-issue-tool-design.md)。后续尚未写出的消息协议、仓库事项生命周期、列表交互、运行适配细节按上述授权继续设计；无需等待逐项批准，不表示这些文件已经写完或真实能力已经实现。

当前原型仍为上一版内存演示，尚未补入可选已有会话、页面创建后的自动准备与真实 REST／SSE。设计基线与演示完成度分别记录。

## 3. ②测试：完整流程与五项决定

可点击路径：六项总览→看测试页面→勾选可能收费→确认→原型控制“调用开始／结果未知”→查询原结果→稍后查看→模型页“查看原结果”。“模拟次数额度未知”展示不能确认；“模拟运维核查关闭”只演示内部已取得停发依据后的候选结果，不是用户能解除真实未知的按钮。

| 决定 | 推荐 | 理由／代价 |
| --- | --- | --- |
| T01 固定候选 | 只测已保存的一个模型、连接和Key版本；有草稿先保存，不加“测试全部” | 能确定哪一套配置得到观察；每模型分别测试。 |
| T02 费用确认 | 预留1次请求，用户明确可能收费；首批不显示估算金额 | 不引入没有可信来源的价格数据；次数上限不能控制供应商金额。 |
| T03 最小探测 | 固定短文本，无工具/图片/流；输出min(16,模型上限)，候选30秒 | 探测连通性成本可控；不验证reasoning/vision或完整任务能力。 |
| T04 独立结果 | 登记、实际开始、通过、明确错误、未知、确定未发分开；旧结果只属于旧快照 | 避免“202=通过”；要保留原结果入口和状态时间。 |
| T05 未知收口 | 每actor最多一笔未核测试；未知不重发。运维证明原发送者失去调用能力后可审计关闭，保留unknown历史和已消费次数；之后新测试仍需重新确认；运维关闭不证明供应商已停，迟到确切证据仍可采纳 | 避免重复收费与永久无法操作；增加受控核查责任，不以租约超时冒充停发证据。 |

**金额预算替代**：若要求测试费用必须受货币金额约束，请不采用T02／S05的次数方案，改补价格版本、最大输入输出计量及未知费用预留。两者不同时冒充已采用；当前双方共同推荐次数方案以保持首批最小范围。

## 4. ③认证／发现：统一裁决范围

| 决定 | 推荐及完整范围 | 代价 |
| --- | --- | --- |
| A1 | github.com单一GitHub App用户授权；安装覆盖外仓库可能缺席，coverage如实partial，保留J1完整目标 | 首批不承诺全账号仓库发现，不加PAT或第二种应用登录。 |
| A2 | 同源HTTPS服务端会话；Origin＋CSRF；callback独立state/PKCE/浏览器绑定；Destination为站内类型白名单，覆盖已有会话，消息提交恢复类型明确属于后续发送批次 | 部署需正确域名、HTTPS和App回调；无任意跳转地址，恢复目标仍重新核权。 |
| A3 | 登录/重连各有attemptId及独立查询；当前session有效不能替代原重连回执；错误账号不合并 | 多一套短期尝试记录；断点只查询，不重用code。 |
| A4 | 新尝试使旧未完代次失效；注销只影响请求session所绑定代次；不发可能清掉新Cookie的迟到删除头 | 旧Cookie暂存但服务端拒绝；迟到旧登录Cookie可能要求再登录，不能保证响应顺序。 |
| A5 | 加密保存短期state/PKCE材料；binding绝对7天、会话绝对12小时/空闲30分钟、attempt10分钟、非秘密结果最多24小时；墓碑覆盖绑定及相关会话/尝试有效期 | 有清理及失效管理成本；期限均是本次候选，不是撤权SLA。 |
| A6 | 无cursor续同actor/连接/q的未完发现批次，完成后新首页才新批；每次上游最多2页/5秒，持久待办续扫，批次10分钟；cursor不混批 | 页面可能分次出现候选；空页和扫描失败要区分。 |
| A7 | 读取观察60秒、写重新核实距提交≤15秒；本地代次变立即失效；安装不足联系部署管理员 | 属来源稿候选观察窗口，不保证外部即时撤权；首批不加App安装管理页。 |

精确请求、联合类型、响应、错误和轮询见[认证稿§3—8](authentication-browser-api-draft.md)。发起限流5次/浏览器/分钟、10次/账号/分钟，查询2→5→10→30秒且隐藏暂停，均列入A5候选。旧GET/session及repositories字段保持原契约。

## 5. ④模型API：明确可审的契约边界

| 决定 | 推荐 | 代价／影响 |
| --- | --- | --- |
| P1 对象 | owner私有供应商；完整不可变ProviderRevision；模型行/profile稳定ID，Key替换生成SecretVersion，旧项目固定旧版本 | 更改一个参数也形成新供应商快照，新测试不继承旧版本通过。 |
| P2 输入 | 单供应商1—50模型；Key1—8192 UTF-8字节原样不trim；正文256KiB；其他长度及数值见字段稿§3 | 首批禁隐式删除/共享/默认切换，参数超限明确拒绝。 |
| P3 原子保存 | 配置、密文、模型映射、操作回执同事务；原键先核有权读取，原保存输入按后端M02比较；命中closed_without_save时直接拒绝，不比较虚构输入 | 需要秘密存储及持久操作槽位；终结按P4争用同槽位，不把Key哈希明文公开。 |
| P4 确定拒绝与保存终结 | 新模型保存/应用可查询持久rejected；保存另增closed_without_save，安全终结与原保存在同一唯一槽位串行，未提交时登记禁止迟到提交的终态，已提交时保留原结果 | closed_without_save不伪造原保存输入，不与rejected混成一种回执；不把404当失败，旧项目三写committed-only查询不变。 |
| P5 单次预览 | 测试/应用预览5分钟，绑定actor/固定快照/政策/项目修订；同预览仅一次消费，原操作重放优先 | 版本变化重新预览，不能自动续期后提交。 |
| P6 精确应用 | 专用接口只换model reference与固定版本，完整复制原execution引用/版本/政策；完全同值no-op仍保存回执 | 不能复用现行configuration PATCH；后者提交两引用并重新解析两者。 |
| P7 恢复与保留 | Key发出后清浏览器原文；保存未知可原查询或安全终结，测试/应用继续核原操作。原保存终结响应丢失仍查询或重试同一终结；保存/应用回执随业务历史期，终结占位保留规则见唯一协议；测试30天，unknown责任及不可复用墓碑持续保留 | 清理后有权410，404仍未知；无法凭旧键重建，不能删除终结占位后允许迟到保存。 |
| P8 内部责任 | 一次可能外发许可、次数原子登记、受控证据接收、白名单审计；后端M01—M08全部作为候选细化；queued10分钟只有确定未发才终结，公开结果将not_needed与open及运维关闭分开 | 崩溃可能留下unknown；不声称供应商恰好一次或费用已结算。 |
| P9 Issue配置归属 | 推荐Issue创建事务固定不可变ProjectConfigRevision引用；应用新模型只改变以后创建的Issue所用当前项目配置，原Issue和创建重放保留原绑定 | 在接收供未来执行的真实Issue/待办前落实关系；Key失效须显式阻塞，实际Manager消费和修复入口另行闭合。详见[绑定候选](issue-configuration-binding-design.md)。 |

字段唯一来源：[模型浏览器稿](model-settings-browser-api-draft.md)；内部唯一来源：[模型后端稿](backend-model-operations-draft.md)。测试15分钟新鲜度只是观察提示，不新增“近期测试通过才可保存/应用/建项”的门槛。

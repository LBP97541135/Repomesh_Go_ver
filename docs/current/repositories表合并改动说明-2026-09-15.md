# `repositories` 表合并改动说明（扫描域并入）

相对数据库重构方案 ② 中规划的 `repositories`（仓库档案 + 轮询游标），扫描域并入后需要的全部改动如下。其余 43 张表不受影响。

## 1. 新增列（4 列，扫描域写入）

| 列 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `fingerprint` | text | `''` | **增量扫描闸门**：扫描时记录的仓库最新提交 SHA。重扫先比对它，未变则整仓跳过（不拉清单、不解析） |
| `metadata` | jsonb | `'{}'` | 事实卡（AutoCard）：目录结构、依赖、六机制证据、构建/部署身份、最近提交、对外路由、低信号标记。全库只有一对编解码函数读写它 |
| `test_commands` | jsonb | `'[]'` | 操作者维护的验证命令，扫描永不覆盖 |
| `test_paths` | jsonb | `'[]'` | 验证命令读取路径，扫描永不覆盖 |

## 2. 语义变化（2 列）

| 列 | 变化 |
| --- | --- |
| `languages` | 不再只是登记项：扫描时从构建清单推导填充，重扫刷新时同步更新 |
| `profiled_at` | 扫描域刷新（整卡替换）时会更新为刷新时间 |

## 3. 明确不新增的列

`scan_status` —— 不落库。失败扫描直接不入库、同名无新卡不写库，列里只可能是 `ok`，属死列。失败/跳过信息只出现在扫描作业的进度计数里。

## 4. 保留不变（交付域）

`poll_last_at` / `poll_next_at` / `poll_failures` —— SCM 轮询游标原样保留。**列归属纪律：扫描代码只写扫描列与共享身份列，轮询代码只写 poll 三列，互不触碰。**

## 5. 写入规则（已实现并有测试覆盖）

- 同名 + 新卡 → 整卡替换：更新 `metadata` / `languages` / `fingerprint` / `profiled_at`，**操作者列与 poll 列不动**；
- 同名无新卡 → 不写任何列；
- 扫描失败 → 整行不入库；
- `name`、`url` 唯一。

迁移文件 `internal/database/migrations/0007_scan_catalog.sql`（分支 `feat/scan-domain`），已含以上全部列，在隔离测试库验证过迁移与应用往返。

## 页面与待裁决安排

入口：主界面 → 模型设置 → 具体模型行“用于项目”。沿已采用供应商分栏页面及弹窗视觉，新增[原型片段](../prototypes/model-project-apply.prototype.js)由页面独占，生成器嵌入原模型页；原15份HTML不改。[串联展示](../prototypes/index.html#model-apply)只是原型场景定位。

已采用三项UI安排（不等于完整协议或实现完成）：

1. 弹窗先选有配置资格的项目，再展示“替换后模型”、“替换前模型”及“保持执行配置不变”。模型侧列供应商／模型ID、连接与模型参数固定快照、只读密钥版本标识和测试观察；当前模型仅为替换前对照，保持不变只指原execution引用来源及有效版本。项目修订单独标为预览／提交比较基线，不承诺应用后不变。密钥原文不展示。主要信息可见，参数详情折叠，代价是弹窗需要滚动。
2. 预览条件不完整或发生变化时暂停确认，说明待核实项／变化内容；重新读取后由用户再次明确确认，不自动采用新版本。执行配置原有效版本未知时不允许把“同一个引用”当作精确保留保证。
3. 提交结果未知时保留原应用入口，只核查该次结果；未查到仍未知，不能换键重发。离开弹窗可稍后从模型页继续核查；已确认未保存的冲突回读并重新确认，成功回执后再查看项目当前配置。

# 创建 Issue 时的仓库分析与 Python 插件

用户在[旧项目插件调查](../research/legacy-analysis-plugin-feasibility-2026-09-10.md)后明确：“可以先把仓库关联分析做成在建立issue的时候加一个仓库分析按钮，做成python写的插件”。本轮采用这一入口、能力范围和实现语言；以下交互与接口细节按[持续设计授权](design-delegation.md)补齐。本文是现行设计，按钮、API 和 Python 包尚未实现。

首期解决“这条需求可能涉及项目内哪些仓库、为什么相关”。历史决策分析保留为后续能力，向量数据库不作为首期依赖。Go 与 Python 的职责取舍见 [ADR-0020](../adr/0020-python-repository-analysis-plugin.md)。

## 1. 页面入口与结果使用

在 Issue 创建表单的“本次仓库”区域放置 **仓库分析** 按钮。标题和目标／约束满足创建契约的基本输入规则后可点击，尚未选择仓库也能分析；已明确验收条件一并参与。分析范围由当前项目和发起人的有效访问范围确定。

```text
填写标题、目标／约束、可选验收条件
    -> 点击「仓库分析」 -> 显示分析进度
    -> 查看推荐仓库、关联关系、依据和覆盖范围
    -> 「应用所选建议」 -> 调整本次仓库
    -> 「创建 Issue」 -> 沿用既有原子创建与提交后接续流程
```

分析与手动选仓并行可用。分析不要求 AgentTeams 实例、Manager 或主房间就绪，也不创建会话、Issue、ChangeSet、计划或 Worker。用户关闭表单不会建项；已受理的分析按其独立时限完成或收敛，产生的只是辅助分析记录。

| 页面状态 | 展示与动作 |
| --- | --- |
| 可分析 | 展示按钮；插件停用／不可用时显示简短原因，仍可手动选仓。 |
| 排队／分析中／恢复核查中 | 展示状态，可继续编辑和手动选仓。重复点击不产生第二个相同任务。 |
| 有结果 | 展示推荐仓库、匹配原因、依赖关系、来源及版本；可勾选建议并应用。 |
| 部分结果 | 明示未覆盖材料、读取失败或低信号；可应用有依据的建议，不能把未扫描仓库说成不相关。 |
| 失败／无足够依据 | 保留表单和已有选择，允许重新分析或手动创建。无命中与读取失败分别表达。 |
| 输入已变化 | 保留旧报告供识别，标明“不适用于当前输入”，禁用应用；重新分析使用新的操作身份。 |

结果中每个候选展示仓库、相关原因和证据；关系区区分有源码支持的关系与仅声明／推测的关系。“可能参与”“需联调验证”不等于必须修改该仓库，评分也不表示经过校准的概率。首期使用可展开列表和关系明细，不另建图编辑器。

“应用所选建议”把选中的、当前可选仓库加入现有选择，不静默清掉手动选择；之后仍可增删。只有用户执行此动作才附带分析来源。单纯看过报告或自动收到结果，不改表单，也不附带来源。最终 `repositoryIds` 始终取用户提交的选择，不能由插件再扩仓。

标题、目标／约束、验收条件、项目或相关创建上下文改变时，清除当前应用的分析来源；已有仓库选择保留供用户检查。仅调整最终仓库选择或关联会话不改变分析输入。用表单本地代次隔离不同弹窗、项目和在途响应，旧分析晚到不能覆盖新表单。

## 2. Go 核心与 Python 插件

| 归属 | 职责 |
| --- | --- |
| Go Web／业务模块 | 认证、当前权限、创建条件、分析操作幂等、结果查询；将应用的分析来源与 Issue 创建快照同事务保存。 |
| Go 后台协调 | PostgreSQL 持久分析作业、限额、领取／租约、固定材料、结果校验和恢复；报告索引由 Go 保存，正文沿用对象存储方向。 |
| 受限主机执行 | 启动已登记版本的 Python 分析进程，落实只读材料、资源／时间限制，核查停止及清理；资源按分析作业归属，不伪装成业务 Attempt。 |
| Python 仓库分析插件 | 根据固定材料执行画像、关键词评分、依赖解析与候选归并，返回结构化候选、关系、证据和覆盖范围。 |

首期是一个随产品配套发布、可启停的第一方 Python 包。采用受控子进程：Go 通过受限执行入口运行登记的 `python -m ...` 入口；stdin 接收一个版本化 JSON 请求，stdout 输出一个 JSON 结果，日志走 stderr。用户输入不能成为可执行命令、入口或宿主路径。具体包名、Python 版本、依赖锁定和完整 JSON Schema 在实施时落实。

分析作业可在尚无项目 AgentTeams 实例时运行。一个作业对应一次受控调用；协议版本不兼容时拒绝调用并显示不可用，不影响普通建项。插件版本进入作业与结果，升级不覆盖旧报告。停用后不接受新分析，既有调用按原限额收敛，历史报告仍由核心按权限提供。原型与产品界面无需向用户展示进程或协议细节。

Python 只读取核心提供的受限快照，不直接拥有 RepoMesh 业务表写权、仓库长期凭据或 Docker socket。仓库文件作为分析材料，不执行其安装、构建或脚本。首期规则与关键词分析不依赖模型服务；以后增加 LLM 评分须经核心控制配置、调用范围和预算，保留明确降级状态。

这一分析进程是 ADR-0013 三类 Go 进程之外的局部扩展；Graph／Loop 继续按 ADR-0014 在 Go 后台进程内运行。它不是 Skill 工程恢复开发，也不引入插件市场、任意第三方安装或独立网络微服务体系。

## 3. 固定输入、证据与可用性

分析输入由核心确定：可信项目／操作者、确切标题与描述、验收条件、创建上下文修订、可分析仓库集合，以及每仓 `repositoryId + commitSha` 的固定快照。分页只影响 UI 展示，不能把第一页仓库当作整个项目。受扫描限额影响时明确覆盖范围，不静默丢弃后续仓库。

分析前读取和输出前披露均按当前权限核验。候选只能引用核心传入的稳定仓库身份；未知别名、项目外或不可访问的依赖只表达缺口，不暴露受限仓库正文、路径或身份。提交分析不授予额外访问权。

每条证据包含所属仓库、固定 commit、文件路径、适用时的行段、内容哈希、解析器版本和证据类型。聚合判断引用其基础证据，推断与源码事实分开。无法固定版本的材料列为未覆盖；禁止在一次扫描中逐文件读取漂移的默认分支。

核心保存确切输入及自行生成的指纹；不得信任客户端传来的指纹。结果绑定输入指纹、快照集、插件／算法版本和生成时间，一旦发布不原地改写。仓库后来前进不会让旧报告自动变成新版本报告；页面展示其固定基线，需要最新代码时重新分析。已知创建上下文或权限失效时须重新分析或移除来源后手动创建。

首期复用旧库的五类扫描线索：构建依赖、调用声明、共享资源、部署配置和源码引用，以及稳定仓库身份／别名解析、关键词候选排序和一阶邻居补充。共享资源只作为相关提示；旧库完整 DiscoveryChain、OrganizationLeader 审批、PlanSnapshot 前置和计划物化不迁入此入口。旧模型 JSON 解析失败变成 `REQUIRED / 0.5` 的语义不保留。

## 4. 浏览器接口补充

以下为本轮采用的最小 HTTP 设计；完整机器可读 Schema、存储结构和实际接口尚未实现。身份来自认证上下文，路径中的项目不得由请求体另行覆盖。

| 动作 | 接口与结果 |
| --- | --- |
| 查询按钮可用性 | 既有 `GET /api/projects/{projectId}/issue-creation-options` 增加 `repositoryAnalysis: {availability, reasonCodes}`；availability 为 `available`、`disabled` 或 `unavailable`。它不改变 `canSubmit` 的含义。 |
| 受理分析 | `POST /api/projects/{projectId}/repository-analyses`，必填 `Idempotency-Key` UUID；即本次 `analysisId`。先原子保存输入与持久作业，再返回 `202 Accepted`、`analysisId`、`status` 和查询路径。 |
| 查进度／结果 | `GET /api/projects/{projectId}/repository-analyses/{analysisId}`，首次只向该项目中当前仍有权的原操作者提供；200 返回作业状态及可披露的终态结果。首期轮询，不借用尚不存在的 Issue SSE。 |
| 建项时记录来源 | 既有 `POST /api/projects/{projectId}/issues` 增加可选 `repositoryAnalysisId`；详细校验和原子范围由[创建契约](issue-page-create-api-contract.md)统一维护。 |

分析 POST 仅接受 `expectedCreationContextRevision`、`title`、`description`、可选 `acceptanceCriteria`，长度／规范化规则沿用创建契约；不要求 `repositoryIds`、`issueId` 或会话。核心按整个当前有权且可用于建项的项目仓库集合准备材料，受控限额体现在覆盖说明。未知字段为验证错误。

幂等作用域为项目＋可信操作者＋分析入口＋analysisId。完全相同输入的重放返回同一作业，已终态返回 200，未终态返回 202；不同输入复用同键为 409 `IDEMPOTENCY_CONFLICT`。analysisId 与 creationId 分开，分析受理成功不代表 Issue 已建立。网络错误查原 analysisId；暂时 404 不证明原提交永远不会受理，不能自动换键重复耗费资源。

作业状态为 `queued`、`running`、`recovering`、`succeeded`、`failed`。终态结果不可覆盖；成功结果另带 `quality=complete|partial` 和覆盖说明，成功但候选为空不自动等于“整个项目无关”。失败保留可披露原因，不构造必选仓库。运行结果未知先进入 recovering，核查旧进程及结果后再收敛，不能仅凭超时宣称停止并启动替补；结果采纳同时校验作业身份、领取代次和输入版本。

候选、关系与证据的输出由 Go 校验版本、大小、身份和来源，再发布结果。无权请求按既有错误包装返回 404 `RESOURCE_NOT_FOUND`；输入错误为 422 `VALIDATION_FAILED`，上下文变化为 409 `CREATION_CONTEXT_CHANGED`，无法受理为 503 `ANALYSIS_UNAVAILABLE`，额度耗尽为 429 `ANALYSIS_LIMIT_REACHED`。这些错误仅影响分析能力；最终创建仍按自己的当前条件校验。

分析记录按项目的数据保留与删除规则管理，删除正文后保留不含正文的最小操作占位，同一 analysisId 不复活。引用报告已清理时返回 410 `ANALYSIS_RESULT_REMOVED`，允许用户移除来源继续手动建项；后续清理不能静默抹去已提交 Issue 快照中的来源身份。TTL、并发、单次文件／字节／时长上限和清理调度属于部署配置，必须在启用前落实。

## 5. 页面、接口与后端交付顺序

1. 页面先演示按钮、进度、候选与证据、应用建议、过期和失败回退；模拟结果标明，不能宣称真实扫描。
2. 将旧解析器与关键词排序裁剪成 Python 包，固定输入输出 Schema；用小型多仓夹具验证解析与结果可追溯性。
3. Go 接入分析作业、受限调用和结果查询，补齐创建时的可选来源关联，再验证真实端到端链路。
4. 用真实项目样本评估候选覆盖、误报和耗时；有证据需要语义召回时，再扩展检索适配。历史决策分析另行设计。

实施验收至少覆盖：未选仓能分析；不分析也能建项；应用建议不清空手动选择；编辑或切项目后晚到结果不回填；部分扫描明确覆盖；稳定 commit 与逐条证据可回查；跨用户／项目／失权拒绝；相同分析键不重复作业；重启／超时先核查；来源同创建事务保存；分析失败／停用不阻断手动建项。以上均为待实施验证，不是本轮测试结果。

## 本次展示

[串联原型](../prototypes/index.html#auth-recovery)，顶部“直接查看场景”可找到“登录与重连恢复”。沿RM-UI-PROJECT-ENTRY原r1已用1／3继续r2，不用新名字重置讨论次数。r1用户“正确”仅采用两步创建及授权提示；当前三项恢复UI已按上述准确范围采用。

对应页面说明（具体参数和机器协议不随三项UI一并采用）：

1. 沿用居中登录布局，先说明当前问题，再显示一个主要动作。登录失效时只写“原页面”，隐藏其名称与内容；授权取消允许显式重试。代价是重新登录前看不到具体目标名称。
2. 账号重连与登录分开说明。当前登录仍有效时展示当前绑定账号；结果未知提供“查询本次连接结果”和“稍后处理”，不会因旧登录或旧连接有效显示本次成功。代价是需要独立结果查询协议，当前尚无采用字段。
3. 确认当前身份或本次连接后显式继续，再核目标读权；不自动重放原业务写入。首次登录尝试成功与当前身份有效不同，页面成功文案分别使用“当前登录已确认”和“本次连接已确认”。代价是多一次继续动作。

## 页面动作与API责任草案

| 页面动作／状态 | 已有依据及仍需补齐 |
| --- | --- |
| 当前登录状态查询 | 现行first-batch-browser-api-contract.md §2 GET /api/session，只确认当前稳定身份和独立GitHub连接观察。401清敏感缓存；200不证明某次登录／重连尝试成功。未知时不展示原项目名称。 |
| 发起登录／重连 | 唯一机器候选为[认证浏览器草案](authentication-browser-api-draft.md)：实际路径、严格Destination联合类型、CSRF／Origin、尝试绑定及错误。已成稿但尚未采用；本页不另定义JSON或HTTP状态码。 |
| 查询本次重连结果 | 需有权核查本次尝试与当前连接代次，不能拿现有session端点代替。原型查询维持未知，只有明确标为模拟的场景按钮展示确认结果；无真实查询。 |
| 返回工作区／继续 | 原型只演示缓存导航。协议候选用受控conversation目标恢复原只读会话，服务端按固定路由生成nextPage，继续前再次核主体、项目归属和整个会话内容读权；未知不继续，失权／跨项目／不存在统一返回工作区，不展示原标题。任意returnUrl和客户端路径旁路拒绝。 |
| 授权取消／过期／账号不符 | 文案候选；不展示供应商原始错误正文、code、state、邮箱或未经当前身份确认的账号信息。时间参数、多标签细节及完整错误映射仍待审。 |

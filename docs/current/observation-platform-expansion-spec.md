# 观测平台增量功能 Spec：真实链路、在线评估与样本复核

## 1. 目标、授权与采用关系

本 Spec 响应评委新增的观测建议：查看调用链追踪与聚类归因，关注 TTFT、Token；使用 AgentLoop 预置评估器评估真实执行；将 Trace 或低分样本回流数据集，经人工或 AI 标注形成回归依据。

交付目标是让使用者能回答：**一次任务实际怎样执行、时间和消耗花在哪里、结果是否正确、失败原因有什么证据、人确认了什么，以及改进后是否还会复发。**

用户随后授权按本 Spec 开发，并补充：观测平台必须全本地化；rubric／打分使用 Jev，聚类归因与 AI 初标可调用 DeepSeek API。v1.1 据此替代 v1.0 的云平台集成选择。观测存储、页面、评估调度、数据集与人工标注均在本机；只有明确配置的模型推理出站。真实跨仓任务仍留待后续。`proposed` 表示未验收条款继续按分项判断，不将开发中状态写成全部通过。实施顺序、验收用例和后续实验统一见[验收与实验计划](../plan/observation-platform-validation-and-experiments.md)。

当前实施结果见[本轮报告](../development/2026-09-20-local-observation-jev/README.md)；G0／G1 部分完成，G2／G3 未运行，以逐项矩阵为准。

## 4. 新增功能要求

### 4.1 F01：接入状态与覆盖诊断

设置页增加观测来源、两类模型用途与能力清单。每个来源记录生产者和适配器版本、来源部署身份、最近观测时间、支持的阶段、缺失字段及原因；运行时未接入时明确显示，不用测试 Trace 填补业务状态。

本地分别报告：来源配置、采集成功、OTLP 持久接收、按 ID 可查、Jev 连接、评分完成、DeepSeek 分析、数据集与标注关联。每项保存检查时点和适用范围；仅模型列表读取成功不能证明评分完成。历史结果与最新失败并列可查。

工作台无需云空间凭据。Jev 与 DeepSeek 的 API Key 分别保存到本机 0600 私有文件，界面不回读；评分和分析按固定样本发起，外发材料范围可查看，缺少必要材料时保持不可评。

### 4.2 F02：真实调用链和任务定位

列表支持按项目、Issue、仓库、Task、Attempt、角色、模型、时间、执行状态和数据完整性筛选；详情展示连续操作的父子树、实际时间区间、异步 Links、重试关联及产物／证据入口。

最低采集边界为：需求／规划输入、任务派发与接收、Agent turn、每次模型物理请求、关键工具调用、候选产物、独立验证与人工决定。关键工具至少覆盖契约／代码读取、代码写入、构建测试和交付操作。缺少某阶段保留缺口；不要求采集每次底层文件 I/O 或模型隐藏思维链。

- Issue 可跨多个 Trace；一次连续 Attempt 操作建立运行 Trace。人工等待以进入／离开事实表示，不维持数天的虚构根 Span。
- 同步调用传播上下文；异步派发持久记录来源上下文和消费关系；多仓汇合关联所有参与的前驱。并行分支不得为了显示方便改成串行。
- 业务关联来自可信派发、接收与台账；共同房间、近似时间、Agent 自报 ID 均不能产生 `exact` 绑定。未能确认时保留 `suspected` 或 `unresolved`。
- 一个长期 session 的不同 turn 可以对应不同任务。共享调用保留多方关联和未分摊用量，不向每个 Issue 重复计费。
- 没有父 Span、存在迟到事件、采集溢出或异常中断时，页面显示缺口；不填造父节点、时长和成功终态。
- 时点事实保持原有语义，新增真实区间记录；旧事实不得被重写成运行时调用。

运行时目标仍沿用原 Spec 的原生 AgentTeams／DSH 方向。实施时锁定实际上游版本及事件出口，先复用原生信息，再补最小适配。本轮不为将被替代的 CLI 深挖一套专用解析器；目标运行时尚未就绪时，平台可验收夹具接入，真实采集状态保持待验。

### 4.3 F03：TTFT、Token、耗时与完整性

指标详情可从汇总下钻到物理调用。时间、单位、计量来源、有效样本数和缺失数必须随指标展示；缺值使用 null 和原因，不以零值混入平均数。

| 指标 | 本轮口径 | 特殊处理 |
| --- | --- | --- |
| 模型 TTFT | 从适配层发出物理请求，到收到首个非空生成内容片段的单调时钟间隔；片段可以是 reasoning、文本或工具调用内容，必须记录 `first_output_kind` | 空 SSE、心跳和仅角色声明不算；如需面向用户的首文本延迟另记，不混成同一指标。 |
| 用户首响应时间 | 用户请求被服务接收，到首次有意义的用户可见响应 | 排队确认单列，不用“已收到”冒充生成响应；未采到用户出口则未知。 |
| 模型总耗时 | 发出物理请求至正常结束、错误或取消的时间 | 同时保留终止原因；客户端取消但服务端未确认终止时不假定用量为零。 |
| 输入／输出 Token | 供应商或可信运行时对该物理调用报告的 usage | 记录模型和供应商请求 ID；中间累计 usage 取最终有效值，不逐块相加。 |
| 缓存／推理 Token | 来源支持时按供应商定义保存，并记录是否包含在输入／输出合计中 | 不将本已包含的子项重复相加；估算另列且不冒充计费用量。 |
| 工具耗时与错误 | 调用开始至结果／终止，附工具调用 ID、错误和重试原因 | 必要重试与无进展重复分开判断，不能仅凭调用次数判低效。 |
| 任务经过时间 | 受理至终态或形成可审查交付包 | 模型、工具、启动、排队、依赖等待、人工等待分项；重叠时间不简单求和。 |
| 采集覆盖率 | 可核对的已采物理调用数／来源台账或受控用例已知调用总数；另报字段与归属覆盖率 | 没有独立分母就显示“无法计算”，不能用已收到 Span 自证 100%。 |
| 费用 | 真实 usage 与有版本价格规则形成的估算，或供应商账单事实 | 币种、价格日期和估算／实付分开；无价格则不显示零成本。 |

每次网络重试有独立 `call_id`，同一逻辑操作另有 `logical_operation_id`。进程重放／双路导出相同调用只计一次；实际重复请求即使内容相同也分别计量。团队执行、独立 Verifier 和 Judge 消耗通过 `execution_purpose` 分桶。

归一化时间展示为毫秒；保存来源值和单位，使用整数纳秒或等价精度计算后转换。外部兼容字段和单位由锁定版本映射测试确认，不能因为本地页面用 ms 就直接填入平台字段。非流式请求不从总耗时推导 TTFT；部分来源不可得的 TTFT 单列 `not_supported`。不同首片段语义或流式模式不混合比较。

聚合支持模型／角色／仓库／Task／Attempt；团队总量从去重后的物理调用计算。成功率必须注明是 HTTP 成功、执行成功还是业务验收通过。小样本展示逐次值、中位数及样本量；不以少量运行的 P95 宣称收益。

### 4.4 F04：调用链分析、场景聚类与失败归因

本地工作台承载全部分析页面与任务。DeepSeek 只接收选定样本的冻结材料，结果、原始响应及 usage 保存本地；调用失败不影响已有证据查询。

**场景聚类**用于发现哪类工作慢、贵或失败多。首批主题建议为跨仓接口变更、数据迁移、缺陷修复、依赖升级；主题及说明版本化。本轮用 DeepSeek 按需求／工作场景进行语义归组，初始批次 4—30 条，每簇至少 2 条，其他作为离群点；每个样本必须恰好出现一次，不接受模型捏造成员。配置和参与样本修订固定保存。它不宣称复现官方聚类算法；耗时和 Token 可在分组后对账。未达规模时显示样本不足。

**失败归因**用于解释某次低分或失败。首批业务标签和证据要求如下：

| 标签 | 至少需要的证据 | 不足时的处理 |
| --- | --- | --- |
| 范围／必要仓库漏选 | 获准范围、必要仓库标签、实际选择与扫描依据 | 范围外必要仓库记范围不足；无必要性标签不编造漏仓准确率。 |
| 契约／旧版本被消费 | 冻结契约、发送／消费或实际输入证据、实现／测试结果 | 金额错误本身不能证明交接失败。 |
| 计划／依赖或交接遗漏 | 生效计划、前驱产物、派发／消费关系 | 不用时间先后推定因果。 |
| 工具／不可用或使用错误 | 工具定义、参数、返回、错误及环境 | 区分环境失败与模型选错工具。 |
| 实现／业务逻辑错误 | 目标版本已正确输入、固定候选及失败检查 | 缺输入证据时不能排除上游交接问题。 |
| 验证／组合版本不一致 | 预期与实际运行 SHA／构建摘要 | 先判验收前提无效，不给目标代码下失败结论。 |
| 证据／采集不足 | 具体缺失字段、来源和阶段 | 归因保持 unknown，不强迫归入模型问题。 |

本地结果记录 AI 提议、证据引用、缺失项与人工确认状态。人工修订追加版本；AI 归因只是有证据约束的诊断，不等于已经验证的因果。DeepSeek 只给出分类、简短说明、允许集合内的证据引用及缺失项，不输出 rubric 分数。AI 标签为待人工确认；不得自动批准或合并。

### 4.5 F05：本地在线链路评估与 Jev Rubric

用户指定 rubric／打分统一接入 Jev。初始固定模型 `jev-1.13.0`，同时保留请求模型与实际响应模型。依据 TypeSafe skill，把独立维度作为同一次请求里的 typed questions；Jev 不生成解释，界面说明由固定 reason code 与原始答案组成。

| 维度 | 输入与适用范围 |
| --- | --- |
| 契约一致性 | 冻结规则及实际消费／行为证据；无消费证据时不判断交接原因。 |
| 产物正确性辅助判断 | 固定产物与独立验证材料；不覆盖 Verifier。 |
| 证据可复核性 | 规则、版本、实际检查的关联；是评估可用性诊断，不是交付许可。 |
| 工具与步骤效率 | 完整、有终态的工具轨迹；固定 HTTP 产物明确不包含 Agent 行为时此项为 not_applicable；真实 Agent 缺轨迹时为 unknown。 |

每个可评维度使用 Score 和独立的证据充分性 Choice，先由代码检查必需输入，未具备的维度不发付费问题。保存 score、legend、probabilities、confidence 和 usage；归一化值等于原分除以等级数减一。初始辅助政策为置信度至少 0.8、归一化分数至少 0.75，不称为官方阈值或已完成领域校准。缺证／低置信度保留 unknown 及未采纳的原始答案。所有 Jev 分数为 advisory，业务验收和人工批准独立。

本地在线调度默认关闭，显式开启后只处理已完成、完整且包含可评材料的 Trace。初始每日最多 10 次，可设 1—100；等待窗口默认 5 秒，可设 0—3600 秒。夹具默认排除，必须另勾选允许才能进入协议校准。Judge 自身一律排除，防止递归。界面设置会说明产生模型 API 调用。

付费前写不可变预约，按来源、Trace、输入修订、模型及 rubric 摘要去重；重启不重复计费。网络结果未知或中断保留预约，不自动重试；手动重评创建新尝试。晚到材料改变输入修订后可产生新评估，旧结果保留。超预算、缺配置、缺证和模型错误均可诊断，不阻塞产品执行。需要硬 Token／金额上限时在后续实验 PLAN 固定；每日请求数不是供应商费用封顶承诺。

一次 Issue 可包含多个 Trace；单 Trace 分数不等于整个 Issue 完成。跨仓最终验收仍针对固定版本组合。评估器消耗与团队、验证、DeepSeek 分析消耗分桶，评分过程完成不能变成业务通过。

### 4.6 F06：样本回流与人工／AI 标注

样本来源包括：选中的真实 Trace、评估低分、确定性检查失败、评估器意见分歧，以及按记录的抽样策略选取的高分／普通样本。只收低分会漏掉被误判成高分的错误，不能用低分集统计整体错误批准率。

回流时固定环境、Issue／Task／Attempt、原始 Trace 列表、输入输出、候选 SHA、验证组合、评估结果和证据包版本；同一来源修订重复入库不新增样本，新产物或新证据产生新修订。样本须有可读取的材料，只有本地路径或 hash 不算完成回流。

本地数据集和复核页保存冻结样本、自包含材料、AI 标签与人工标签。首期提供固定模板的人工确认／纠正，不建设任意模板编辑器。离线历史导入明确标为操作员映射，不冒充平台已核验。

标注模板至少包含：任务是否完成、输出是否正确、工具使用问题、是否存在无进展重复、失败类别、证据引用、评估器是否误判、修正理由、证据充分性。原始自动分数、AI 初标和人工最终标签分别保存，记录标注者身份／类型、时间、模板版本和样本修订。

样本处理状态为待标注、AI 已初标、待人工确认、存在分歧、人工已确认；这些状态由本地样本与标签修订投影。AI 初标不能成为“人工确认”的证据。新输入／产物版本出现后，旧人工标签只适用于旧版；不得悄悄继承。

人工确认的样本可形成 regression 数据集版本；另保留不用于调优的 heldout 集。已用于修改 Prompt、规则或实现的样本不能继续算盲测。回流删除／失权后保留必要身份和不可访问状态，停用该版本的可评标记，不继续展示为证据可取回。

### 4.7 F07：交付审核与标注的关联

送审证据包包含需求／契约版本、各仓候选与 diff、实际验证组合、必检结果、缺失项、相关 Trace、自动评估和人工标签。审核者可在 RepoMesh 审核入口查看摘要，在本地工作台复核过程，再回到确切送审产物。

交付审批记录决定人、时间、理由与当时证据版本；样本标注记录对该样本的质量判断。二者通过不可变产物／证据身份关联，但不能互相代行。候选 SHA、组合或证据变化后，页面必须显示旧决定适用范围并要求新版本复核；实施需验证当前审核接口是否真的检查客户端所见版本，不能只依据源码注释。

观测服务不能调用批准／合并接口代替人作决定。评估高分、标注为正确、平台任务成功均不能直接打开交付闸门。

## 5. 数据契约、故障与兼容约束

以下为待实现的观测内部契约，不是新产品数据库表或已发布 HTTP Schema。字段复用原 Spec，实施时只对实际新增结构升版并补映射测试。

| 记录 | 最小身份与内容 |
| --- | --- |
| 来源能力记录 | source_id、来源／适配版本、支持阶段和字段、检查时间、缺失原因。 |
| 运行关联 | project／issue／repository／task／attempt、运行实例与 session／turn、trace／span、绑定依据、exact／suspected／unresolved。 |
| 调用记录 | source_id、call_id、logical_operation_id、retry_of、execution_purpose、真实起止、终态、模型／工具、输入输出引用及计量。 |
| 导出记录 | 目的地作用域摘要、数据修订、字段策略版本、接收状态、平台查询证据；不保存明文凭据。 |
| 评估记录 | 受评对象与输入摘要、grader 配置摘要、平台任务／结果、评分尝试、原始响应、分数尺度、判定、证据及错误。 |
| 样本与标注 | source revision、dataset／item 映射、材料版本、模板、AI／人工标签、确认人和修订链。 |
| 交付关联 | review_request、证据版本、candidate／combination、相关评分和标注身份。 |

必须满足以下约束：

1. 旧 `repomesh-observe/0.1` 事件和 `repomesh-dataset/1` 数据集继续可读；旧证据不补造运行细节。新增结果、修订和同步记录使用独立版本／记录类型，评估重跑不改原记录。
2. 同身份同内容幂等，同身份冲突内容拒绝并可诊断；区分本地档案复制与真正独立运行，统计按来源部署及调用身份去重。
3. 原始材料与归一化投影分开保存；只读来源不接受标签覆盖，新标注／映射写当前档案并引用原来源。
4. Jev／DeepSeek 不会读取本机路径或私有 hash。模型请求使用选定的自包含证据材料；正文缺失时降为不可评，不授予模型任意文件或数据库访问。
5. 脱敏保留契约内容、工具关联和版本的必要语义；密钥、认证头和无关个人信息不外发。输出截断记录位置／原因及可取得的完整引用；脱敏后不能完成的评价如实标缺。
6. 采集／导出从业务路径隔离，网络上报异步且有界；队列、磁盘或网络失败必须可见。容量、单条大小、保留周期和重试上限写入部署配置，不无限缓存；丢弃／缺口写独立状态，不隐性阻塞派工。必要业务事实仍随原业务事务保存。
7. 保留当前回环监听和跨站访问限制。模型调用仅由后端发起，不为此开放本地档案服务至公网；产品权限边界保持。
8. 证据删除、平台数据过期或访问权改变时，显示引用不可用及原因；旧评分作为历史结果保留，但不可宣称仍可复核。实施时记录本地和模型服务各自保留策略。

| `internal/database/migrations/` | 仅在可信身份／事实确实无存储处时新增窄迁移 | 实施时按当时 main 分配编号，不预占 0058 等号码；不修改已应用迁移。 |
| 文档与验证目录 | 更新本地说明、配置用途、实际完成交接；保存新批次证据 | 历史报告保持原结论；产品 API 或表结构实际变更时同步接口总册与数据库设计。 |

新增本地服务能力按以下责任划分；路由名与 payload 在实施契约中落定，不以表内用途名假装现有端点：

- 查询：能力与接入状态、分页 Trace／调用、指标及覆盖率、平台结果、样本修订和标注摘要。
- 管理：验证选定目的地、提交允许范围内的导出、导入真实平台结果与标注、选择固定输入发起或登记评估。
- 产品侧只提供经项目授权的身份和证据关联；本地页面的管理写入口沿用现有同源及请求头保护。

每个新接口在实现前写清授权范围、分页／筛选、版本／幂等键、响应与错误语义；身份冲突、版本冲突、证据缺失、能力不支持和外部超时分别表达。业务 API 若有变化，必须同步[接口总册](api-design.md)及关联测试。首期不建设通用 API 代理、任意 SQL 查询、任意用例编辑器或自动 Prompt 优化器。

具体用例及必需证据见[验收与实验计划](../plan/observation-platform-validation-and-experiments.md)。每项状态必须是 PASS、FAIL、NOT_RUN 或 BLOCKED，并附代码／运行基线与证据；没有接入环境不能改记 PASS。

| 门槛 | 覆盖内容 | 允许声明 |
| --- | --- | --- |
| G0 本地平台准备 | 契约、身份、指标、状态、导入回读、页面与旧档案兼容；受控协议夹具验证 | 平台对所列协议和用例已准备好。 |

| G2 真实运行接入 | 选定原生运行时的真实模型／工具调用、精确业务身份和计量对账 | 该任务范围的真实执行可观测。 |
| G3 真实任务闭环 | 真实跨仓产物、独立验收、评估与人工确认、修复后复验 | 完成所列任务闭环；收益仅按实验样本及规则表述。 |

G0 可以先用模拟供应商测试；G1 的真实模型请求单独验收，G1、G2 均通过后才能进入完整 G3。真实运行时未就绪时不得用 CLI 夹具给 G2 签字。调用链、TTFT／Token、Jev／DeepSeek、在线评估和标注各有分项状态；“页面能打开”不是任一完整门槛。

## 8. 后续实验要求

后续实验采用新计划的 E0—E4：先验证平台接入，再完成真实执行采集和折扣案例，之后开展冻结条件的版本对照与人工复核。每次保存需求、输入版本、起始仓库 SHA、运行构建、模型配置、预算、样本清单、验收器、评估器、标签与全部终态。

## 9. 依赖、官方依据与执行状态

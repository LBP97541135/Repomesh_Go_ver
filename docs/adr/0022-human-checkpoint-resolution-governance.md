# ADR-0022：人工检查点决议治理——唯一落库入口、漂移单兜底与聊天批复定位

人工检查点（HITL）链路的机制设计是完整的：Worker 阻塞或到达受控节点时自动开立审查请求（`human_review_requests`，含卡点、证据版本、摘要）；人工决议必须经正式端点（`checkpoint-decisions`）提交，服务层校验项目拓扑与人工授权后，原子地写入决策表并把请求置为已决。

2026-09-14 的数据摸底实证：生产库中 **26 张待审请求全部 pending、零条有决策人、决策表为空**——不是机制缺失，而是三条真实缺口叠加。本 ADR 把诊断固化为治理决策，作为 Go 版 HITL 链路设计的第一输入。

## 实证的三条缺口

1. **聊天旁路**：Worker 在 Matrix 房间发出 BLOCKED 消息后，人工答复发生在聊天里，从未经正式端点落库。工作照常继续，审计链断裂——审批单永远挂起。
2. **模式选择入口缺失**：监管策略设置界面（三档：全自动／关键卡点／逐步确认）在工作台改造中失去宿主（旧发现面板退役，替代卡片构建后未挂载），用户无法在开工前选择模式。主项目拓扑携带强制 `exception_escalation` 卡点运行，每次阻塞必然开单——单据泛滥的源头。
3. **政策漂移死锁**：决议入口按「当前」拓扑复查卡点是否启用。上述 8 个项目在单据开立后被重建为 auto 模式、授权人清空，复查永不过——**存量 pending 单据经正式入口永远无法决议**（三层锁：政策复查 + 授权为空 + 早退守卫重复校验）。

## 决策

1. **唯一落库入口**：人工对检查点的决议，必须且只能经正式端点写入决策表并关闭请求。聊天里的批复有两种合法定位，Go 实现必须**二选一并写明**：要么被程序适配为一次正式 API 调用（聊天批准 → 自动落一条带来源标注的决策记录），要么明确声明聊天回复不构成决议、仅是沟通。不允许第三种「事实上有效但无处落库」的状态。
2. **政策漂移存量单的兜底**：pending 请求本身即「开单时卡点启用过」的事实，不得以当前政策否决。决议授权规则分层：档案内授权人照常可决；政策已漂移且授权人不在时，**管理员可兜底清偿**；其余账号维持拒绝。附带回归测试（管理员可清偿漂移单／非管理员仍被拒）。
3. **监管策略入口常驻工作现场**：模式选择不得依赖独立页面或已退役的面板——它必须出现在「开工确认」的同一个视野里（Python 控制台已补挂于物化确认上方，门控：未物化时可见、物化后策略定死即收起）。
4. **存量清偿即治理动作**：对历史漂移单据的批量清偿经由正式端点完成，每条留下决策人、理由与时间——清偿行为本身进审计链。

## 证据与实现状态

- 实证查询：26 张 pending 全部 `exception_escalation`、8 个项目拓扑全部漂移为 `auto` + 空卡点 + 零授权人（SQL 连表核实）。
- Python 控制台已修复：决议服务移除当前政策早退复查、新增漂移分支（授权人照常／管理员兜底／他人拒绝），API 传入真实管理员身份；项目模块 52 项测试全绿，含两条新增回归测试。
- 监督策略入口已于 Python 控制台工作台补挂；审核台（决策按钮、正式端点）此前即完整存在。
- Go 版实现状态：未开始。本 ADR 为 HITL 链路（开单 → 展示 → 决议 → 关闭 → 审计）设计的第一输入；决议表的表结构与漂移判定语义照搬 Python 修复的裁决。

## 与既有决定的关系

不改变 [ADR-0003](0003-plan-change-authorization-and-activation.md) 的计划许可边界，不改变 [ADR-0019](0019-conversation-issue-separation.md) 的会话／Issue 关系；「聊天批复适配为正式调用」的具体协议属于消息协议专题，实现时另行细化，本 ADR 只锁定「必须二选一、必须落库」的治理约束。

# ADR-0007：Graph／Loop 插件形式与执行行为

用户采用 D1—D7 的 Graph／Loop 建议，并提出以插件形式组织这项能力。RepoMesh 的 Graph／Loop 以插件形式提供，具体流程继续由 Skill 指导形成版本化计划；许可、计划应用和任务启动遵守 ADR-0003，由 RepoMesh 实际控制。

插件化是已确认方向；后续已确认插件在后台协调进程内按独立模块运行、随后端发布，状态持久保存，见 [ADR-0014](0014-in-process-graph-plugin.md)。2026-09-09 用户进一步采用复用最新 AgentTeams 原生 DAG：仓内建图、依赖校验和候选就绪计算复用上游，RepoMesh 模块保留跨仓协调、业务结果适用性及循环约束，不重写完整 DAG 引擎。职责补充见 ADR-0014／0015，详细规则和版本证据统一见 [Graph／Loop 现行专题](../current/graph-loop-design.md)。具体接口和上游任务映射仍待细化，本记录不表示受控接入已经实现。

## D1：首期流程形态

支持顺序、并行、汇合和有界 Loop；仓内当轮 DAG 使用上游原生能力，跨仓依赖及 Loop 推进由 RepoMesh 控制。运行中改变已获准目标、范围或上限等形成业务计划的版本化变更；按 [ADR-0015](0015-round-scoped-upstream-dags.md)，已获准范围和上限内的下一轮属于执行进展，上游任务安排更新另记，不因此新建业务 Plan Version。首期不引入任意嵌套流程语言。用户通过 Manager 的自然语言入口调整，直接编辑图仍为后续待办。

插件形态不改变授权和执行边界。图中节点、许可记录与实际派工需要一致，不能仅由插件页面或 Skill 文本保证。

## D2：检查结果与后续工作

| 检查结果 | 后续处理 |
| --- | --- |
| 通过 | 满足其覆盖范围内的对应依赖，仍核对当前组合和证据有效性。 |
| 业务缺陷 | 交相关仓库 Team 定位和修复。 |
| 环境阻塞 | 处理未满足的验证前提。 |
| 暂无法判定 | 补充诊断及证据。 |
| 需求待澄清 | Manager 按当前模式选择解释或请人决定。 |

新工作都要检查有效计划和许可，结果标签本身不授予无限新增任务或重试的权限。

## D3：默认上限

| 工作 | 默认上限 |
| --- | --- |
| 每个修复 Loop | 3 轮 |
| 诊断补证 | 2 轮 |
| 环境自动恢复 | 2 次 |

默认值落实到具体计划，预算或时限先到则先停止。变更按 ADR-0003 重新判断许可，累计消耗不因换计划清零。计数落点、组合循环及 Attempt 重试的关联需实现前细化，不通过这些技术细节绕开获准上限。

## D4：提前停止

连续两轮出现同一失败且没有新增有效证据时，结束当前循环，由 Manager 说明未完成原因。采用新策略需要形成可解释的计划变更，不无限重复等价操作；YOLO 仍遵守现有授权和预算边界。

## D5：多失败分支汇合

各仓修复分别提交新候选，Manager 选定明确的新组合，再组织受影响验证。仍适用的证据可以保留并说明复用依据，不要求每次无差别重跑所有检查。

## D6：受阻分支和其他工作

已获准且不依赖受阻结果的工作可以继续；依赖该结果的工作等待。如果需要应用新计划，仍按 ADR-0003 暂停受影响的上游 Project。业务上的依赖判断不代表首期上游已经支持仅暂停单个分支。

## D7：迟到结果

旧 Attempt 结果保留历史，并核对所属计划、Attempt 和固定组合。已被替代的执行结果不能直接解除当前依赖；可能复用的证据需重新判断适用性。

## 待细化和验证

- Graph 的进程内运行与计算／派工职责已按 ADR-0014 确认；具体接口、注册和兼容方式、插件版本与计划的关联仍待细化。
- 当前获准轮次映射为有限 DAG、由 RepoMesh 控制后续轮次的方向已按 [ADR-0015](0015-round-scoped-upstream-dags.md) 确认；具体上游任务标识、工具路径、状态和恢复映射仍待细化。
- 许可和实际执行之间的受控路径、暂停收敛、迟到结果与重启核查。
- 图的具体页面布局及执行状态刷新仍需专题细化；后续页面与创建接口进展见[现行导航](../current/README.md)，不能把 Issue 详情 SSE 扩成所有图的刷新契约。插件形式不等于已经选定某个前端插件框架。

Controller replan 在存在 in-progress/submitted 任务时拒绝，pause 不停止在途任务；当前基线 paused 后直接 replan 的 409 已有真实 HTTP／MinIO 证据，停派工与改图仍需受控衔接。静态、组件与真实服务证据的范围见[现行专题](../current/graph-loop-design.md)，均不能替代 RepoMesh 全链路验收。ChangeSet 的记录与交付规则见已确认的 [CS1—CS14](../current/changeset-design.md)，其与 Graph、计划和证据的具体接口映射仍待细化与验证。

## 决定来源

用户明确回复“D全部：Graph按推荐。并且我希望能做成插件的形式”。本 ADR 记录其采纳的行为和插件方向，不将 H—K 的建议一并视为确认。后续 H1—H15、I 的主要规则及 J1—J3 已分别确认，页面与接口继续形成后继决定，当前状态见[现行交接](../current/HANDOFF.md)；上述确认来源只说明本次 Graph／Loop 决定的范围。

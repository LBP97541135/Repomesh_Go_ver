# ADR-0004：按自动化档位决定缺失业务规则的解释

验证过程中可能发现业务规则尚未定义完整，同一结果因解释不同而得到不同结论。按照 [ADR-0006](0006-manager-entry-modes-and-skill-driven-execution.md)，审批模式经 Manager 请人决定；YOLO 由 Manager 选择并记录解释后继续执行和验证。

## 已确认规则

- Agent 可以指出缺失规则，提出业务解释、建议及对应检查。
- 需要审批的模式中，Manager 在当前会话呈现解释、建议和影响；经人决定后，用于受影响检查。
- YOLO 不为该问题等待人工确认。Manager 选择并记录解释，注明决定来自 Manager，再继续执行和验证；不能写成人已确认。
- 此授权只用于补充缺失规则，不能覆盖已有明确要求。扩大权限、提高预算上限或放宽已明确验收条件，按 ADR-0003 和 ADR-0006 的模式边界处理。
- 保留采用的解释、决定来源及受影响检查，并关联相关验收和计划版本；记录结构待细化。
- 获得解释不表示测试通过或新计划生效。仍依据固定组合及实际证据判断；涉及计划调整时遵守 ADR-0003。

## 场景

frontend F1 + backend B1 的“支付状态筛选”需求未说明“已支付后退款的订单是否包含在已支付结果中”。

审批模式由 Manager 给出建议及影响，请人决定。YOLO 由 Manager 采用并记录一种解释，继续执行测试。两种情况下都需要记录 P01 的实际状态、可见范围、请求及响应等与本项有关的证据，才能形成检查结论。本例不预先决定所有项目都应包含或排除退款订单。

## 待细化

当前阶段按 [ADR-0006](0006-manager-entry-modes-and-skill-driven-execution.md) 统一 YOLO，审批能力后续开发。后续计划审批人的资格已在 [ADR-0003](0003-plan-change-authorization-and-activation.md) 第 1.8 节确认；业务解释决定的具体权限与有效授权核验仍需细化，不能将计划代审资格自动视为修改业务验收规则的权限。有效权限、决定记录结构及解释变化后的证据适用性细节继续在后续技术设计中明确。受阻分支及其他工作的处理已见 [ADR-0007](0007-graph-loop-plugin.md)，不改变按模式分配解释权。

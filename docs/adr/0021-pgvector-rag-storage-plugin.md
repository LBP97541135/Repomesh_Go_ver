# ADR-0021：pgvector 作为 RAG 存储插件，向量检索语义下推数据库

RepoMesh 的决策链读投影（`decision_chain_nodes`）之上有一层 L3 语义检索：每张决策表存储一个嵌入向量，按余弦相似度回答「历史上有没有相似决策」。此前的存储是 JSONB 列 + 应用层全量载入内存计算余弦——语料小的时候可用，但语义上它只是「存在 JSON 里的附件」，数据库对相似度一无所知，语料增长后检索退化为全表扫描。

本决定采纳 **pgvector**（PostgreSQL 向量扩展）作为 RAG 存储层：嵌入列升级为 `vector(1024)`，建余弦 HNSW 索引，检索以 `ORDER BY embedding <=> :query LIMIT :k` 在数据库内完成。向量能力因此成为「装在数据库引擎上的插件」，而不是应用代码里的一段算法。

本决定为设计收口：Python 控制台（参照实现）已于 2026-09-14 落地并验证；Go 侧对应迁移（`0007`）待实施，设计输入即本文。

## 决策与理由

- **维度与模型是一份契约**：`vector(1024)` 硬绑定当前嵌入模型 BAAI/bge-m3 的输出维度（硅基流动提供，配置于 `REPOMESH_EMBEDDING_*`）。更换嵌入模型意味着一次新迁移加全量重嵌——维度不匹配的写入被数据库直接拒绝，杜绝静默错配。数据版本边界因此显式。
- **索引选型 HNSW + `vector_cosine_ops`**：余弦算子与降级路径的 Python 余弦是**同一种距离**，保证走索引与走降级给出同一份排序。HNSW 为近似索引，以极小概率的召回损失换数量级的速度，是行业标配取舍。
- **检索语义下推**：距离定义（`<=>`）、排序、截断（limit）、门槛（相似度下限）全部是查询的显式参数，在数据所在地执行；应用层只接收胜者。不再有藏在应用代码里的隐式排序行为。
- **能力可插拔（降级开关）**：存储实现启动时探测 `pg_extension`——扩展在场走 SQL 侧 ANN；不在场自动回落 JSONB + Python 余弦（SQLite 测试孪生天然走此路径）。插件缺失是**降级**，不是故障，日志明说。这同时是「复制到新环境时哪些工具可替换」问题的标准答案：关系事实源不变，向量库装/不装插件一行配置，模型层随配置换。
- **模块归属不变**：两张表仍在 `decision_chain` 域的 schema 内，写入路径 B8 原则不变（写路径永不调用嵌入服务，批量刷新离线补向量）。

## 备选与否决理由

- **继续 JSONB + 内存余弦**：小语料可用，但「RAG 库」名实不符；语料到万级即不可用，且检索语义无法被数据库索引与审计。已由本决定替代（原实现即回滚目标）。
- **自研向量检索服务**：引入一个新进程、新部署单元、新故障面，换取的能力 pgvector 以一个扩展提供；运维成本不成比例。
- **外挂专用向量库（Milvus/Qdrant 等）**：能力溢出——决策链检索不需要分布式与多租户向量集群，而多一个有状态外部依赖直接违背「干净环境一键复现」。

## 验证证据（Python 控制台，2026-09-14）

1. 干净数据库全量迁移链一次通过（含 `CREATE EXTENSION vector`、列类型迁移、HNSW 建索引、存量 29 条向量无损 cast 搬运）。
2. 5 组真实查询（线上嵌入）SQL ANN 与 Python 余弦 **Top-5 完全一致**，分数一致到小数点后四位。
3. `EXPLAIN` 关闭顺序扫描后确认走 `ix_decision_embeddings_embedding_hnsw` 索引扫描；默认优化器在小表时正确选择顺序扫描。
4. 全量测试套件 2937 通过（含 SQLite 孪生路径与降级探针路径）。

## 回滚与实现边界

- 回滚：Alembic downgrade 将列退回 JSONB 并删除索引，存量数据经 `::text::jsonb` 无损返回。
- Go 侧实施时直接复用迁移 SQL 与检索语义；未装插件环境的降级探针语义（`nearest` 返回空即回退 Python 排序）一并照搬。
- 本 ADR 不改变 [ADR-0020](0020-python-repository-analysis-plugin.md) 的 Python 分析包定位，也不涉及会话与 Issue 关系（[ADR-0019](0019-conversation-issue-separation.md)）。

# ADR-0014：Graph 插件在后台协调进程内运行

RepoMesh 首期将 Graph／Loop 插件放在后台协调进程内部，按可替换的独立模块组织，随后端一起发布。按 2026-09-09 的复用补充，插件承担跨仓协调与循环策略，仓内 DAG 的建图、依赖校验及候选就绪计算复用 AgentTeams；后台提供上游观察并继续负责实际派工。计划、轮次和累计消耗持久保存在 PostgreSQL 中。

本决定细化 [ADR-0007](0007-graph-loop-plugin.md) 的插件方向和 [ADR-0013](0013-web-coordinator-host-executor-processes.md) 的进程职责。采用进程内调用，减少首期独立服务及通信维护成本，同时接受插件与后台一起升级、严重插件故障可能影响后台的代价。当前只做设计和本地文档整理，未开发、安装或部署插件。

## 已采用的职责与运行方式

- Graph／Loop 插件运行在后台协调进程内，作为独立模块被调用，不为它另行部署一个流程服务；随后端配套发布。
- 后台通过执行 Adapter 取得上游 DAG 的候选就绪节点和状态观察，连同有效计划、已采纳结果及循环进展交给插件；插件判断跨仓前驱、业务结果适用性与停止条件，不另写一套通用仓内 DAG 引擎。
- 插件返回计算结果，实际启动仍经过后台的计划、权限、预算、容量和 Worker 占用核验。插件不直接派 Worker，不以节点就绪代替执行授权。
- 计划、轮次和累计消耗由后端持久化到数据库。重启后从保存的记录恢复并核查实际执行，不能依赖进程内计数或重新从第一轮开始。
- 顺序、并行、汇合、有界 Loop 及修复／诊断／环境恢复上限继续按 ADR-0007 执行；候选、组合和证据适用性继续按现行验证及 ChangeSet 规则处理。

## 支付状态筛选示例

~~~text
后台读取有效计划、固定组合、已采纳结果及上游候选就绪节点
        |
调用 Graph 插件
  核对跨仓依赖、业务结果适用性和循环停止条件
        |
返回“验证节点就绪”或“允许继续修复／应停止”等计算结果
        |
后台重新核验适用约束，再安排执行或记录停止原因
~~~

例如，当前组合的前置条件满足后，插件可以返回对应验证节点已就绪；后台仍要核验独立验证者、有效权限和容量，才启动验证。修复达到既定停止条件时，不再因重新调用插件或后台重启而增加一轮。

## 取舍和待细化内容

进程内调用更便于首期部署、调用和排障，独立模块仍保留测试及替换位置。代价是不能独立部署或升级插件，也没有独立进程提供的故障隔离。异常处理、执行耗时约束、兼容性核验及后台恢复仍须设计和验证，不能声称所有插件故障都能被安全隔离。

具体输入输出格式、模块接口、注册与版本兼容方式、状态提交和并发校验、停止条件计算的证据来源、与上游任务的具体映射仍待细化。“把当前获准轮次映射为有限 DAG”的方向在后续讨论中另行确认，见 [ADR-0015](0015-round-scoped-upstream-dags.md)，不属于本次确认范围；不据此选定 Go 动态插件机制、第三方插件框架、任意热替换或额外运行平台。

Skill 工程仍按 ADR-0009 整体暂缓；Graph 插件的运行方式不启动 Skill 的管理、分发、加载或版本隔离能力。当前仍统一 YOLO，实际计划应用和任务启动继续由 RepoMesh 控制。

## 确认来源

在解释插件放在后台进程内、仅返回流程计算结果、派工由后台控制、状态落数据库，以及减少一个独立服务与故障隔离较弱的取舍后，用户回复“采用，确认”。据此记录上述运行方式和职责。

## 2026-09-09 补充：复用原生 DAG，收窄 Graph 模块职责

用户原话：“就按照最新版本的，按照建议RepoMesh 可以复用上游 DAG，不需要把所有能力重写一遍。 然后你来清理，更新文档，Graph/loop这一块”。据此补充既有决定，不新增 ADR 编号。

- 原“插件计算依赖”的表述限定为跨仓依赖与业务放行条件；仓内 DAG 的原生建图、依赖／环校验、就绪查询和结果状态推进通过上游执行 Adapter 复用，不将 TeamHarness 算法整体移植为 Go。
- Graph 模块继续在后台进程内运行，接收后台提供的上游观察并返回本地业务判断；远端调用、凭据、资源预留和实际启动由后台及执行 Adapter 负责。上游不可用或观察陈旧时先核查，不以本地替代引擎静默继续派工。
- 接受耦合上游确定版本、工具语义与升级契约的代价，保留必要的受控接入和小范围补丁方向；不以复用为由取消计划、权限、预算和业务验收检查。
- 本次最新源码基线为 2026-09-09 查询的 main `eeaab64391ccaec9118e84977f538aefd40720d6`；最新正式 release 为 v1.2.3，二者区分记录。具体版本证据、能力分工、未实现项见 [Graph／Loop 专题](../current/graph-loop-design.md)。

本补充细化本 ADR 的职责及 ADR-0015 的复用方式；不替代原进程、持久化、配套发布与故障影响取舍，也不选定动态插件框架、桥接协议或具体补丁实现。

# ADR-0013：Web、后台协调与受限主机执行的进程划分

RepoMesh 首期采用同一 Go 工程、配套版本一起发布，分别运行 Web、后台协调和受限主机执行三类进程。它们可位于同一台服务器，通过持久记录和受控调用协作，将页面交互、长期任务协调和服务器环境管理分别承担，以便独立维护运行过程并集中管理高权限操作。

本决定细化 [ADR-0010](0010-technology-stack-and-modular-monolith.md) 的模块化单体及后台可独立运行方向，承接 [ADR-0011](0011-agentteams-controlled-integration.md) 的受控执行要求，不改变 [ADR-0012](0012-issue-scoped-upstream-projects.md) 的 Issue 映射。本轮仅确认设计，未编码、安装、部署或进行远端操作。

## 已采用的职责

**后续局部扩展：** [ADR-0020](0020-python-repository-analysis-plugin.md)允许三类 Go 进程之外的可选 Python 仓库分析进程。后台协调保存分析作业，受限主机执行职责增加已登记分析进程的启动、限额、停止核查与回收；分析可早于 Issue／项目实例建立。下文原三类业务进程划分与配套发布原则保持，不能再将其解释为禁止这一明确扩展。

| 进程 | 职责 | 执行边界 |
| --- | --- | --- |
| Web | 接收页面请求、核验访问、保存用户输入、返回查询结果和推送变化。 | 正式提交先持久化需求及待处理工作，再返回稳定 Issue 身份和状态，不等待整个构建或验证完成。 |
| 后台协调 | 处理持久任务、落实有效计划、安排资源、采集结果和核查恢复。 | Manager 仍作业务判断；后台程序校验权限、计划、预算、容量和归属并落实安排。它不是新的 Manager，也不是业务 Worker 身份。 |
| 受限主机执行 | 准备和管理明确归属的实例／Attempt 运行环境，落实容器、目录、网络、挂载和资源限制，核查停止并回收。 | 只接受经过核验的有限操作，不开放任意宿主命令或挂载入口。Web 和 Agent 不直接持有 Docker socket。 |

三类进程属于同一后端工程，配套发布，不按每个领域模块再建立独立网络服务。进程数量也不表示只能运行三个业务任务；业务 Worker 的并发仍由团队上限、项目额度及全局容量控制。具体启动命令、二进制打包方式、连接协议和进程副本数另行细化。

AgentTeams Controller 继续管理其负责的 Agent runtime。主机执行进程处理明确分配给它的环境操作，具体资源需登记生命周期管理者，同一资源不由两个控制程序竞争管理。停止请求和实际停止、环境回收及历史删除分别处理。

## 支付状态筛选示例

~~~text
用户提交“增加支付状态筛选”
        |
Web：核验并持久登记 Issue、主 ChangeSet 和待处理工作
        |
后台协调：确保实例就绪，接入 Manager，按有效计划安排任务
        |
受限主机执行：落实经核验的独立 Attempt 环境准备
        |
Agent 在独立环境中开发、构建及验证
        |
后台采集并核查结果 -> Web 提供摘要和变化通知
~~~

关闭浏览器不取消已提交工作。Web 单独重启时，后台可继续处理已经持久登记的工作；未完成的请求和断开的连接仍需恢复。后台重启后按持久记录核查真实运行状态，不把全部任务重新启动。整台服务器故障仍影响同机进程，恢复依赖持久数据及实际状态核查；三进程划分不等于高可用或跨系统只执行一次。

## 原因与代价

将交互和长期协调分开，避免页面请求生命周期决定业务执行是否继续，并允许分别定位和处理故障。把容器引擎等高权限操作集中到职责较小的进程，使调用范围可以在实际执行入口核验；仅分进程不自动形成权限隔离，仍须落实运行身份、凭据、调用授权和参数约束。

代价是需要启动和监控三个进程、管理内部调用权限、处理超时和配套升级。接受这些成本，同时保留同一工程、一起发布的组织方式，控制首期维护复杂度。

尚待细化：领域模块归属与调用方向、Agent 工具入口的监听和路由、进程间协议、凭据分配、队列领取、占用与恢复算法、资源生命周期明细、启动停止顺序及运维方式。Graph 插件运行位置已由后继 ADR-0014 确认，不再是未决方向；本决定不将架构 v1 的其他具体建议一并冻结，不恢复 Skill 工程或后续审批模块开发。

## 确认来源

后续进展：Graph 插件运行位置按 [ADR-0014](0014-in-process-graph-plugin.md) 单独确认，未倒填为本次三进程选择的确认范围。

用户在三类进程建议后要求“什么意思，你解释一下我再同意”。在说明同一工程可运行多个进程、支付状态筛选的处理链路、各进程职责、Manager 与后台的分工、权限集中、重启和整机故障的区别，以及部署维护成本后，用户回复“同意，采用”。据此记录上述进程划分。

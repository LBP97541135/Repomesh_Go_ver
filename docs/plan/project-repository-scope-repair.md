# 项目、仓库与 Issue 范围修复计划

2026-09-19。按本次用户要求制定并实施；基线为 `9a34331` 加工作区已有修改。

## 目标与规则

操作顺序为：创建／选择项目 → 明确接入仓库 → 在项目内创建 Issue。

- 项目可以先保存名称、用途，尚无仓库时不能创建 Issue。
- 账号可访问仓库仅是接入候选；项目仓库以 `project_repositories` 为准。
- Issue 工作范围必须是项目仓库的非空子集；项目增仓不扩张已有 Issue。
- 候选推荐、审批、计划与任务不能突破 Issue 已确认的范围。
- 不自动选择列表第一个项目、仓库，不在创建 Issue 时隐式创建项目。
- 保留既有业务记录及工作区修改；历史越界数据不得靠自动增仓变成合法数据。

## 实施顺序

1. **后端项目与创建条件**：允许空仓库项目保存，复用显式增仓接口；统一创建条件、权限与最终提交检查。
2. **后端发现与规划**：候选池限定到项目及 Issue 工作范围，精确关联扫描画像；审批、计划和任务落库再次校验，计划采用实际批准的分档。
3. **数据库约束**：新增迁移，为任务保存可约束的 Issue／仓库身份；处理兼容与已有数据，阻止新写入越界任务。
4. **前端操作流**：扩展项目管理为基本信息保存、仓库接入；统一项目状态；项目仓库页按项目查询；新 Issue 显式确认仓库，固定提交输入与幂等键。
5. **验证与交接**：增加有意义的项目隔离、审批与任务约束回归测试，执行 Go 全量检查及两套前端检查，更新 API、使用说明与交接记录。

## 验收标准

- 空项目可保存、可后续增仓，空项目不能创建 Issue。
- 两个项目的仓库、候选、计划和任务不串用；同项目内未纳入 Issue 的仓库也不能被静默加入执行。
- 绕过前端提交项目外／Issue 范围外仓库时，后端拒绝且不产生部分业务记录。
- 数据库直接写入越界任务被拒绝；兼容旧数据不会扩大项目范围或删除历史。
- 审批中排除的仓库不进入计划；伪造仓库名不能通过审批或任务落库。
- 切换、创建项目后侧栏和工作台一致，旧请求不覆盖新项目数据。
- 选择仓库支持分页；网络失败不冒充空列表，不触发自动建项目。
- 同一次提交重试沿用原键和确切输入，避免重复项目／Issue。

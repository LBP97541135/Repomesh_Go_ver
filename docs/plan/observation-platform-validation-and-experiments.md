# 观测平台增量功能：实施验收与后续实验

唯一功能依据为[观测平台增量 Spec](../current/observation-platform-expansion-spec.md)。本文负责开发顺序、验收用例、后续实验与证据要求，不重复定义产品业务协议。用户已授权开发和 Jev 验收，并明确全本地观测。v1.1 替代原云平台门槛：Jev 负责 rubric／打分，DeepSeek 负责聚类归因／AI 初标，本机负责调度、档案、数据集及人工复核。真实跨仓任务仍留待后续；具体已运行项目由实施记录逐项给出。

## 1. 顺序与交付单元

| 阶段 | 工作 | 依赖 | 可交付成果 |
| --- | --- | --- | --- |
| P0 契约与来源核查 | 锁定基线、实际运行时事件出口、物理调用身份、计量口径；确认旧格式读法 | Spec 与当前源码 | 来源能力清单、字段映射、契约样本；未知项与阻塞门槛。 |
| P1 本地平台准备 | 新记录／查询、来源状态、Trace 关联、指标、导出包与本地评分／标注修订 | P0 | G0 本地验收报告；受控夹具与生产样本明确分开。 |
| P2 本地 AI 流程 | Jev typed rubric、DeepSeek 主题／归因／初标、本地在线评估及人工确认 | P1；模型 API 配置 | G1 报告，真实模型响应与本地记录；受控材料只证明该流程。 |
| P3 原生运行时接线 | 可信派发绑定、模型／工具／turn 原生采集、用量对账与故障观察 | P0／P1；目标运行时可用 | G2 真实采集报告；未实现的运行时能力另列阻塞，不纳入观测工程偷偷重写。 |
| P4 真实任务闭环与对照 | 跨仓任务、独立验证、本地评估、样本回流、人工确认、机制修改和复验 | G1 与 G2；实验 PLAN 已冻结 | G3、E2—E4 报告；每项结论限定任务与样本。 |

P2 与 P3 没有互相冒充的完成关系。无需云账号。模型未配置时可先完成模拟供应商测试；目标运行时尚未就绪可完成 P1／P2。平台准备验收、原生采集验收和真实业务验收分别签字，不以一个总 PASS 隐去缺口。

每个实施单元开始前核对当前 main 及该 worktree 的本地修改，只在本次独立分支工作。本文不授权切换其他本地分支、合并其他未提交改造、升级共享服务或清理旧证据。

## 2. 验收矩阵

每条记录执行者、时间、产品／适配器／模型配置版本、测试输入、预期、实际、状态和证据路径。PASS 必须满足整行标准；外部能力不可用记 BLOCKED，未做记 NOT_RUN，实际不符合记 FAIL；已有实现或局部证据但不满足整行记 PARTIAL，不计 PASS。验收记录和实验报告分目录保存。

### 2.1 本地准备 G0

受控 Trace 使用独立 `source_id` 和 `subject_kind=protocol_fixture`，所有页面、CSV 和评估输入保留该标记；固定折扣产物继续标记 `synthetic_fixed_product`。同一个标记不能被导出或回读路径丢失。

| ID／功能 | 输入与操作 | 通过标准与证据 |
| --- | --- | --- |
| OBS01／F01 | 无配置、配置存在、接收确认、查询命中、最近失败分别构造 | 分项状态与实际一致；配置改变后不沿用旧核验；截图及状态响应。 |
| OBS02／F02 | 两个同时活跃的 Issue，共享房间／session；不同 Task／Attempt | 所有已知绑定均准确，交叉归属为零；缺绑定的事件保持 unresolved；保存预期关联表。 |
| OBS03／F02 | 同步调用、异步派发、两个并行仓库汇合、人工等待 | 父子、Links 和等待类型正确；并行不串行化，缺父不补造；导出与回读逐边核对。 |
| OBS04／F02 | 子 Span 先到、终态迟到、进程中断、来源缺一段 | 展示 partial／待补齐和原因；恢复后保留原 ID；不把已停止采集误判为业务成功。 |
| OBS05／F03 | 可控单调时钟下：请求 t0、空帧 t1、reasoning t2、文本 t3、结束 t4 | TTFT 为 t2−t0，首片段类型明确；用户首文本另计；空帧不计；平台映射按已锁单位往返一致。 |
| OBS06／F03 | 非流式、首片段前失败、生成后取消、usage 缺失 | TTFT／用量只在可观测时有值；未确认计费用量为未知；汇总分母与原因可核对。 |
| OBS07／F03 | 同调用重复上传、两个来源副本、一次真实重试、累计流式 usage | 重放不重复计量，物理重试分别计；最终累计值不相加；缓存／推理子项不双算。 |
| OBS08／F03 | 同一批包含团队执行、Verifier、Judge 和共享调用 | 三类消耗分开；团队总量等于去重物理调用之和；共享调用不在各 Issue 复制；缺独立分母不显示 100% 覆盖。 |
| OBS09／F03 | 输入固定开始结束与重叠分支，附已知正确／失败结果 | 经过时间与分段解释准确，重叠不简单相加；HTTP 成功率和业务通过率不混名；时点 Span 不进入运行耗时。 |
| OBS10／F05 | 错映射、缺工具轨迹、评分缺失、评估器报错和已知业务检查失败 | 缺输入不可评，执行成功不等于业务成功，缺分不补满分；评分不覆盖确定性失败。 |
| OBS11／F05 | 终态前后到达、超过迟到窗口、同结果回读两次、补证后重评 | 不以不完整输入形成已确认结论；重复导入幂等，补证生成新输入修订，旧结果可查；Judge Trace 不再次触发评分。 |
| OBS12／F06 | 同 Trace 修订两次入库，旧样本 AI 初标、人工改错，再提交新产物 | 同修订唯一；AI／人工、原分数／修订标签分开；新产物不得继承旧人工确认；操作者／模板／时间可追溯。 |
| OBS13／F07 | 审核页面打开后候选 SHA 或证据版本改变 | 旧评分与决定只关联旧版；当前操作检测版本漂移并要求新版本复核；不会通过标注调用批准或合并。 |
| OBS14／F01—F07 | 旧档案、旧 CSV、只读来源及损坏／冲突内容 | 旧格式可读且不补造运行信息；只读来源不改写；新记录冲突拒绝，损坏明确报错。 |
| OBS15／F01—F07 | 模型服务断开、超时、限流、队列达到配置上限、磁盘写失败、重启 | 业务线程不等待远端；资源受配置约束；失败／缺口可见；成功落盘的数据可重放；超时重试不虚称 exactly-once。 |
| OBS16／F01—F07 | 带假密钥、认证头、无关个人信息和评分诱导文本的输入 | 外发包只含允许材料；缺失／脱敏可见；被评文本不成为评分指令；跨项目读取及非法来源请求被拒绝。 |
| OBS17／F02—F07 | 从列表筛选 Issue，展开调用，查看指标、评分、样本与旧版本；空集、缺证、失权 | 路径可走通、状态诚实、链接身份一致；错误不变空成功；浏览器记录和网络请求可复核。 |
| OBS18／F01—F03 | 固定本地协议工作负载，采集关闭／开启交错运行，另测模型服务超时 | 预热后各 30 次，采集中位额外耗时不超过关闭中位值的 5% 与 5 ms 两者较大值；零未记录丢失，内存／队列不超配置；保留逐次数据与环境。 |

OBS18 是本轮确定性夹具的初始工程门槛，不是实际模型性能收益。计时测试使用可控时钟验证语义，开销测试使用真实时钟；若环境噪声足以改变结论，记录无效测量并调整环境重测，不放宽阈值后把同一批结果改为通过。实际业务开销在 E1 单独报告。

| OBS24／F06 | 从 Trace、低分与高分抽检保存样本，AI 初标后本地人工纠正 | 冻结样本唯一，新增选样原因不丢；AI 与人工分开，旧标签保留；原始版本变更不会沿用旧确认。 |
| OBS25／F05—F07 | 原始材料含另一供应商凭据／嵌套 JSON；模型超时、结果落盘失败后 HTTP 重试 | 出站前脱敏并保留策略；付费前预约，重复提交不重复调用；预约可关联实际结果或未知状态；不提供云配置。 |

OBS21 证明模型和本地流程能运行，不要求裁判对全部样本永远一致。错误被误评或正确产物因缺证被置 unknown 必须保留，并进入后续校准；辅助阈值不构成发布门禁。

## 3. 代码验证与文档验证

实现阶段按改动执行检查：

```bash
# 观测核心及管理工具
go test ./internal/observepipe ./internal/observeui ./internal/observability ./cmd/repomesh-observe
go test -race ./internal/observepipe ./internal/observeui ./cmd/repomesh-observe

# 改动跨进程、身份或业务协议时执行全量产品检查
go build ./...
go test ./...
go vet ./...

# 产品前端实际受影响时
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend run lint

# 修改产品 API／数据库设计时
python3 docs/development/2026-09-15-api-redesign-01/scripts/verify_api_doc.py
```

涉及数据库的验收在隔离测试库运行并配置 `REPOMESH_TEST_DATABASE_URL`，保存通过／失败／跳过数量；未设置连接导致跳过不能作为数据库通过。实际改动 `web/` 或配套发布链时，补根工程对应前端检查。浏览器验证覆盖新增入口与状态，并保存所用真实／夹具数据范围。新测试应验证身份、时间、失败恢复和人工版本等行为，不只复述字段结构。

设计阶段只进行了文档核对；用户随后授权本地实施和模型调用。当前代码、检查、真实模型调用与未执行项见[实施报告](../development/2026-09-20-local-observation-jev/README.md)。真实任务 E1—E4 的后续边界不变。

## 4. 后续实验设计

### 4.1 通用冻结项

每轮新建 `docs/development/<日期-观测实验主题>/PLAN.md`，运行前填写：

- 目标与假设，实验 E 编号、用例／数据集版本、development／regression／heldout 分组。
- 真实运行二进制版本、工作区补丁摘要、AgentTeams／DSH 与适配器版本、数据库迁移、实际服务及模型配置；仅源码 HEAD 不足以证明运行版本。
- 每仓起始 SHA、分支／worktree、测试数据与数据库初态、扫描／契约／计划输入、缓存／记忆策略和外部服务条件。
- 每个 Variant 的唯一改动、全部 Trial 编号、运行顺序、预设重复次数、Verifier 与评估器冻结配置、采样率和结果选择规则。
- 每 Trial 和整轮的模型 Token、最大轮次、工具／网络重试、超时、本地评估样本数与模型金额上限；未填不得启动外部调用。
- 终止和恢复条件：预算耗尽、环境版本不符、采集断链、外部服务持续失败、身份错误或证据不可保存；停机结果仍保留。
- 参与人工标注／审核的人、匿名化和呈现顺序、数据外发范围、证据保留位置与期限。

试验只使用明确指定的仓库和隔离环境；工作区、数据库、对话、记忆与构建产物按 Trial 恢复。不得修改用户的其他本地分支，也不得借实验清理共享容器／卷。记录配置不构成实施授权，本次用户说“真实任务待会做”的边界保持有效。

### 4.2 E0：平台与协议验收

目的：证明数据接入、展示、评估及回流链路可用。依次执行 OBS01—OBS25，其中真实模型部分在实际模型配置完成后开展。数据包括受控时序、已知 Token、重复／乱序／缺失记录、正常与错误契约产物。

输出：G0／G1 分项报告、本地模型与调度配置快照、Trace ID 清单、字段对账、评分原始结果、回流样本和人工标注记录。结果只表述协议／平台行为，不计算 Agent 成功率，不将夹具量计入真实样本量。

### 4.3 E1：真实运行时采集校准

目的：先证明“采得对”，再研究“做得好”。选一个小型真实任务，至少涉及一次文件读取、一次实际工具执行和一次模型请求。按实际支持情况覆盖流式、非流式；另用明确标记的可控故障运行观察重试和取消，不混入自然失败统计。

通过条件：可信 Task／Attempt 与运行 turn 关联准确，工具输入结果可追溯，供应商／运行时 usage 与观测记录一致；至少一条真实流式路径能说明 TTFT 首片段来源与时钟边界。来源无法提供的字段明确记录。采集开启与关闭的额外开销单独测量，不把两次模型随机耗时差认作观测开销。

输出：G2 报告、实际调用对账表、缺失清单和运行版本。尚无确定采集总数来源时，覆盖率只能报告已核对范围，不报全局 100%。

### 4.4 E2：真实跨仓闭环——折扣契约

公开需求：价格服务和订单服务按固定契约表达应付比例。输入 10000 分、应付比例 8000 基点，应付及订单持久化金额均为 8000 分。选择真实参与仓库，在运行前冻结其职责、起始版本和兼容要求。复用旧固定产物只作为验收器正反校准，不能替代本次 Agent 产出。

实验步骤：

1. 从正式 Issue 进入选仓、规划、各仓任务执行；保存实际输入、候选代码和运行链。
2. 构建固定候选组合，独立核对实际运行 SHA／构建摘要，执行跨服务请求并重读订单持久化金额。
3. 同时检查用户要求中已公开的边界条件；首轮包括 0 基点、10000 基点及整数金额样例。若包含舍入或非法范围规则，必须在开跑前明确，不事后添加隐藏业务要求。
4. 将真实 Trace 交给 Jev rubric 及契约专项规则，检查评分输入是否包含所需材料。
5. 对失败、低分、评估分歧及至少一条高分样本回流；人工核对实际版本与证据并确认标签。
6. 若有可证实的问题，只修改选定机制形成 Variant B，从相同起点复验；保留 Variant A 全部结果。

前提错误（装错版本、环境不可用）记 unknown／环境故障；业务行为与已冻结规则冲突记 fail；全部必检通过才记 pass。若基线自然成功，不故意改坏后称发现了自然问题；故障注入使用单独 case ID 与标签，仍可用于校准归因和人工复核。

成功交付包括真实代码／提交和证据包，不要求为完成实验自动合并 PR。形成可审查交付与人工合并分别记录。

### 4.5 E3：小规模版本对照与评估器校准

首轮是探索性实验：选择 3 个已冻结的真实任务用例，每个用例 Variant A／B 各 3 次，共 18 个独立 Trial。用例覆盖跨仓契约修改、带依赖的缺陷修复和数据／接口兼容；具体仓库和验收规则在开跑前确定。若预算不足，先修订并冻结 PLAN，不在看到结果后删减失败 Trial。

每对 Variant 只比较一种明确的工程机制变更，例如契约输入版本校验；模型、预算、起始代码、验收器与 Judge 配置保持一致。用固定并记录的随机种子安排交错 A／B 次序，避免把时间段、模型服务负载或不同缓存误当改进。

| 结果维度 | 报告口径 |
| --- | --- |
| 交付质量 | 首次联调通过、固定预算内最终通过、失败、未知、未进入验证；给分子／分母及逐 Trial 结果。 |
| 正确性与覆盖 | 必要仓库漏选及无关选择须有人工标签；没有标签的只作案例分析。 |
| 效率与消耗 | 成功者与全部尝试分别报告终止时间、修复轮次、真实 Token、采集缺失和评估消耗。 |
| 重复动作 | 按冻结规则与人工确认区分无进展重复和必要恢复，保存判据。 |
| Judge 误判 | 人工核对 18 个 Trial 的关键标签，报告误接受、误拒绝、unknown 与意见分歧；AI 初标不是人工真值。 |
| 聚类／归因 | 记录主题、成员、错分、离群点、证据支持和人工修正；未达本地最小规模则延后效果结论。 |

改进假设、主指标和可接受退化范围必须在 PLAN 中写定。探索性结果允许“未改善”或“证据不足”；3 次重复不支持稳健尾延迟或普遍成功率声明。使用这些任务调优后，追加未参与调优的 heldout 任务验证；具体数量依据预算在观察结果前固定，不复用已泄露的答案集。

### 4.6 E4：人工 review 与标注回归

目标分别为减少交付补证成本、提高评估／归因的可靠性。冻结一组匿名证据包，含正确、已知错误、证据不足三类，并随机化呈现。比较原证据展示与新增 Trace／评估／标注关联展示时，采用不同的等难度样本并记录分配，避免同一人先看过答案导致后一次天然更快。

记录首次打开、提交决定、补证与中断；经过时间和可确认的实际操作时间分开。报告错误批准、正确候选被拒绝／搁置、补证轮数和每样本用时。复核人有分歧时保留各自标签及裁决依据，不用多数 AI 投票冒充人工裁决。

人工确认后冻结 regression 数据集版本；同一改进版再次执行时，核对老问题是否复发及高分误判是否减少。回归运行单独计 Trial 和 grading attempt，不能覆盖第一次的坏样本。没有足够的人和样本时只交付流程验证，不宣称人审效率提高。

## 5. 证据目录与报告要求

每轮新建目录，建议内容如下；它们是后续产物要求，本次不创建空的“已验收”文件：

```text
docs/development/<日期-观测实验主题>/
  PLAN.md                  # 运行前冻结项、预算与退出条件
  REPORT.md                # 实际结果、限制、失败与恢复
  acceptance-matrix.json   # OBS01—OBS28 分项与证据引用
  manifests/               # 代码／运行／配置／数据与规则摘要
  trials.jsonl             # 所有 Trial 与终态，不筛掉失败
  reconciliations/         # Trace 身份、usage、TTFT 与模型响应对账
  evaluations/             # 原始与规范化结果、外部身份、输入映射
  annotations/             # 样本修订、原始标签、人工确认与分歧
  checks/                  # 本地检查和浏览器证据
```

原始大文件及受限内容保存在私有证据档案，仓库报告写受控引用和摘要，不提交密钥、原始认证头或无关个人信息。仅有摘要而没有可访问的受控取证方式，必须标为无法复核。实验目录的 CSV／JSON、截图与总结应能按同一个 Trial、Trace 和产物版本对应。

报告明确区分：源码阅读、受控协议测试、真实模型 API 操作、真实运行采集、真实业务验收、人工标注和探索性收益。最后列出未执行项、阻塞原因、误判与未解决缺口；不得用构建通过、平台接收成功或模型高分代替它们。

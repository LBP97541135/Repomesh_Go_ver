# 文档评审：决策演进与现行一致性

评审日期：2026-09-09。范围为 `docs/adr` 的 19 篇 ADR、`docs/current` 原有 27 篇文档，以及总导航、领域术语和相关证据入口。由三个审查 Agent 分别检查 ADR 演进、技术专题一致性、交接与通信历史，主 Agent 汇总、维护导航并复核修改。

## 结论与判断方法

发现多处**已确认设计没有同步到旧正文、流程图、验收场景和交接摘要**的问题。主要集中在会话／Issue 分离、实例准备时点及创建契约的采用范围，足以让不同读者实施出不同的对象关系和入口行为。已有后续确认能够解决这些冲突；本轮据此修正文档，没有新增产品决策。

判断以明确确认来源和定点替代关系为准，不以文件更新时间或 ADR 编号一概覆盖。原始用户回复、持续授权及双方通信记录分别核对；设计已采用、协议尚未编制、原型尚未演示、运行尚未验证分别表达。工作树中已有的大量未提交修改是评审基线，没有回退到 Git HEAD。

## 经核对不构成冲突的差异

| 看似不同的表述 | 正确解读 |
| --- | --- |
| 一会话多 Issue，但各 Issue 的上游 Project、计划及 Attempt 独立 | 用户交流关系与执行归属不同。ADR-0019 不取消 ADR-0012／0017 的隔离和占用约束。 |
| 模块化单体，但有 Web／后台协调／主机执行三类进程 | 同一工程和配套发布可以运行多个进程；ADR-0013 是对 ADR-0010 的细化。 |
| Graph 为插件，但在后台进程内运行 | 插件表示模块职责与替换边界，不等于必须单独部署。ADR-0014 明确接受配套升级和故障影响代价。 |
| 当前 YOLO，同时保留人工审批规则 | 审批是已记录的后续能力。当前 YOLO 仍受权限、预算、计划和验收约束，Git 合并仍由人处理。 |
| Skill 工程 ADR 为 accepted，但 implementation 为 deferred | H1—H15 方向已同意，整个模块开发明确延后；持续设计授权没有取消暂缓。 |
| 创建返回 committed，但房间不可进入或 Manager 尚未接收 | 本地事务提交、外部准备、消息投递、接收和实际执行分别取证。未知结果核查不等于重新创建。 |
| 架构／后端专项整体 proposed，内部创建契约已采用 | 混合成熟度需要逐节说明，不能全篇批准或全篇退回待确认。 |

对创建契约、Manager 双入口机制与后端专项中的本地原子提交、幂等作用域、可信来源、结果核查及权限重检，未发现需要另作产品取舍才能解决的相互冲突。此结论只限现有文档，不能替代实现验证。

## 仍需设计或验证的范围

本轮不把缺失设计补写成已确认决定。后续工作顺序由 [HANDOFF](HANDOFF.md)统一维护，关键边界如下：

1. **Manager MCP 的完整协议：** 名称、角色和业务职责已采用；完整输入／输出 Schema、可信操作身份生成、来源句段与恢复仍需编制。一条消息可包含多项工作，不能用会话或消息整体作为永久唯一创建键。
2. **仓库事项与房间拓扑：** 仓库事项每仓数量、生命周期、Leader 房间共享粒度、一个 Issue 的反向多主会话能力尚未决定。
3. **消息与更正：** 自然语言明确目标已采用；语义误判、批量命令、澄清／更正、跨事项顺序和并发恢复的具体协议尚不完整。
4. **运行准备与消耗归属：** 提交后准备的触发已确定；基础服务与成员、配置门槛、无 Issue 讨论的工具／费用／预算、容量与闲置回收仍需细化。不能承诺“只启动 Manager”已经可用。
5. **实际控制与恢复：** room/session 隔离、上游受控工具、资源代次、未知结果核查、故障收敛、多目标应用及权限变化仍需运行验证。
6. **创建之外的页面和协议：** 项目创建、列表通知、会话消息、完整工作聚合、登录接入和数据库结构尚不完整。原型缺可选已有会话和页面创建后自动准备；真实 REST／MCP／SSE 未实现。

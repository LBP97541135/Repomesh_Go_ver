## 原型入口与评审问题

原型保存在本任务的持久展示目录，以对话内可交互预览呈现：

文件为离线交互片段，使用本地模拟数据，无服务请求。宿主支持设计选项时可切换布局、业务场景、连接状态及内容密度；普通本地预览使用底部布局与场景切换栏。所有交互只保存在内存，刷新会重置。URL 参数不是业务归属或持久化依据。

本轮要回答的问题：Manager 工作区默认如何安排对话、进度与详情，用户能否快速知道当前发生了什么并找到依据。

| 布局草案 | 信息安排 | 评审重点 |
| --- | --- | --- |
| A：对话优先 | 顶部状态与执行／验证／交付摘要，下方 Manager 对话；计划、证据、交付及历史切换查看。 | 主线是否清楚，详情是否容易发现。 |
| B：对话与详情并排 | 左侧项目导航，工作区内对话和详情并排；窄屏上下排列。 | 对照说明和证据是否有帮助，信息密度是否过高。此三栏形式未采用。 |
| C：进度时间线 | 工作区先呈现需求与当前进展，随后提供详情入口和 Manager 输入。 | 重新进入事项时是否更容易理解进展，持续对话是否方便。 |

三个方案都是候选设计。图以可点击的只读依赖示意呈现，没有编排编辑功能。未制作 Skill 页面、审批功能或密钥管理表单。

## 可以操作的场景

- 返回订单系统项目入口，查看配置概览，新建并正式提交模拟 Issue。
- 新提交显示稳定 Issue／ChangeSet 归属及等待项目准备，不冒充实例 Ready 或 Manager 已接收。
- 向 Manager 发送模拟补充，只显示已登记、待处理，不伪造模型回复或计划生效。
- 查看计划与依赖，点击节点查看归属和等待原因。
- 查看组合、逐项检查与证据结构；后续场景中可选择 C1 历史，不替换当前组合。
- 查看 draft PR、部分合并、取消及完成历史；所有 PR 编号与版本均为示例，没有真实外链。
- 展开页面下方的接口对应与本地交互轨迹。

预设 11 个场景：首次准备、等待资源、执行中、验证发现缺陷、计划部分应用、建议正式审查、部分合并、部分权限失效、外部结果未知、已取消历史、已完成历史。

权限失效示例仅撤销 backend 推送能力，明确保留读取权限，因此仍能查看既有两仓材料；不能推广为仓库读取权限撤销后仍可见。原型中的新建示例包含 backend 写入要求，在该受限场景中不能提交；正式产品仍须允许只涉及可用仓库的需求，本原型尚未实现自然语言范围判断。

支付示例采用前端 F1 的分页参数缺陷、修复为 F2，后端 B1 保留。C1＝F1＋B1，C2＝F2＋B1，C3 表示最终实际合入组合。这些代号只用于演示，不替代现行文档中的通用规则。计划部分应用场景额外明确原始要求包含导出筛选，以说明 V2 补齐遗漏验收范围的原因。

## 页面与接口对应（全部为草案）

| 操作 | 拟设计接口 | 状态与约束 |
| --- | --- | --- |
| 项目入口 | `GET /api/projects/{projectId}/entry` | 当前权限下可见的需求、配置可用性与受限原因。读取不准备实例。 |
| 正式提交 | `POST /api/projects/{projectId}/issues` | 需求、明确范围、独立操作标识、所见配置修订。服务端重新核验；示例 `201` 只表示 Issue、主 ChangeSet、待办已登记。 |
| 工作区快照 | `GET /api/issues/{issueId}/workspace` | 三类进度、对话、准备状态、修订、更新时间和来源；空记录如实表达。 |
| 发送补充 | `POST /api/issues/{issueId}/messages` | 独立操作标识；已登记、投递、Manager 处理和计划变更分别表达。 |
| 变化推送 | `GET /api/issues/{issueId}/events`，SSE | 变化通知、重复／乱序处理和缺口补查的方向示意；完整游标契约未冻结。 |
| 计划／组合／历史详情 | 按明确 Issue、版本和对象查询的 REST 接口 | 不直接照数据库表生成 CRUD；路径、分页、证据正文权限与完整结构后续逐项讨论。 |

调用者为浏览器中的当前用户，均经 RepoMesh 核验当前项目和对象权限；浏览器不持有上游管理凭据。独立逻辑操作沿用幂等规则，同标识不同输入拒绝；修改既有目标须校验目标修订。首次创建的配置修订校验方式仍待设计。HTTP 超时先核查，不能换标识盲目重建。SSE、重连和证据读取同样遵守当前权限。

上述只是接口说明和模拟轨迹，没有实现 REST／SSE、幂等存储、历史分页、后台调度、真实权限判断、上游适配或完整恢复算法。预览中的连接开关只是页面状态示例，不证明事件重放或持续权限核验已经实现。

## 已做检查与局限

已用浏览器检查项目入口、新建模拟需求、补充消息、分页缺陷详情、历史组合选择、宿主设计选项、连接中断与恢复；对 1024、736、360 像素宽度检查代表场景，查看明暗主题。JavaScript 语法检查通过。

检查中修正了受限预览容器不允许原生表单提交的问题，改用本地按钮交互。上述是原型的可操作性检查，不是产品功能验收。

原型尚未覆盖完整项目接入、账号授权、所有权限撤销类型、提交结果未知的可操作恢复、历史分页与所有异常组合。当前只比较页面信息层次及若干关键交互；具体按钮位置、准备期间是否允许追加消息、结束后输入方式、接口路径／字段／状态码等均未冻结。

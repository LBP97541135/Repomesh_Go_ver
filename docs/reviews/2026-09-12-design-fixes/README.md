## 检查范围

- [文档检查脚本](check_documents.py)扫描指定四个源目录及本记录，检查本地 Markdown 文件链接、JSON 围栏语法和修订文档尾随空白；结果写入[document-checks.json](document-checks.json)。脚本同时与原审查哈希比较，记录本轮改动和新增源文件。
- 原型检查使用原始事件处理代码和有限 DOM 替身，验证模型测试观察与应用预览的一致性、快照隔离和 Key 终结候选状态。生成器输出与源片段另作一致性检查。
- 对候选协议进行人工场景推演和非主要修订者的复核；这不等于数据库并发、真实权限或外部运行测试。

## 实际检查结果

页面 agent 重用原审查中的事件探针，得到：模型行 `本次测试通过`，应用预览 `本次测试通过`；模型配置中的旧 `test` 字段仍为 `untested`。修复通过共享观察读取完成，没有把测试结果写入不可变配置。探针原始复现方法保留在[原页面审查](../2026-09-12-design-readiness/page-review.md)。

| 行为组 | 已验证的模拟行为 |
| --- | --- |
| 模型测试通过 | 列表和应用预览显示同一快照的通过观察，旧预览保持原快照。 |
| 模型测试失败 | 两处观察一致；失败不新增“禁止应用”的门槛。 |
| 模型测试未知 | 两处保持未知；供应商／版本切换隔离旧结果，未测试和未知不新增应用门槛；有未保存草稿时仍先提示保存。 |
| Key 终结先成功 | 关闭弹窗不终结；终结响应丢失保留 saveId，同一终结重试不建新保存；取得终态才解锁，迟到模拟成功不能再提交已关闭操作。 |
| Key 原保存先成功 | 终结取得原提交结果，不撤销配置，不再保存一次。 |
| Key 原保存已拒绝 | 返回原确定拒绝，按明确未保存恢复草稿。 |
| 新供应商的 Key 终结 | 确认未保存后须重新填入 Key 演示占位，再明确创建新 saveId；没有残留秘密占位绕过填写。 |

页面分支另通过 27 个脚本单元语法检查、5 个嵌入家族与生成结果一致性检查，以及 15 份原 HTML 完整性检查。`index.html` 仅由生成器再生。10 个首批 Destination 变体已作字段／路由对应检查；后续消息提交类型未冒充首批可用接口。

## 独立复核

Key 修订者对配置绑定专题和首批持久化增量作只读复核；配置修订者对 Key 浏览器／内部终结协议、总包 D06／P4／P7／P9 和开工条件作只读复核。两者未发现新的实质事务冲突。主审据复核进一步明确：单独开发 Issue 持久化代码，也不能跳过接收真实业务前的固定配置关联要求。

主审另核认证恢复中的操作不存在与业务资源不存在：原操作查询专用 404 保持未知，有权 410 保留清理结果说明，均不能当作业务资源不存在而丢掉恢复入口；页面修订者同步唯一认证与恢复文档。上述为文档独立复核，不计作历史设计师的技术轮次或用户采用。
